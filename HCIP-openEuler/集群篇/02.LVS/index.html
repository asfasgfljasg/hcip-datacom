    02.LVS

    1.LVS核心理论

    1.1.什么是LVS？

    LVS(Linux virtual Server)是Linux内核级别的负载均衡解决方案，由章文嵩博士1998年创建，工作在传输层，性能及高。官网：http://www.linuxvirtualserver.org

    LVS实际上是基于IP地址的虚拟化应用，根据请求中的目标IP和端口以及负载均衡算法决定转发至哪台后端服务器。

    1.2.为什么使用LVS？

    随着Internet的爆炸性增长以及日常生活中的重要性，服务器上的工作压力也迅速增加，为了攻克服务器的过载压力问题，有两种解决方案：

    • 单服务器解决方案：升级服务器的硬件性能，但以当前的业务量级对于大型业务来说单台服务器硬件性能是有很大的瓶颈的，且此种方案成本极高。
    • 多台服务器解决方案：将多台服务器组成负载均衡集群，在负载增加时可以轻松的在集群中添加新服务器满足不断增长的需求。且此种方案对单台服务器的性能并没有很高的需求，也就意味着即使每一台服务器的硬件配置都不是很高，但只要数量够多同样可以应对大量业务请求。

    构建集群的方法：

    • 基于DNS的负载均衡集群：

    • DNS负载均衡是构建网络服务集群的最简单方式。DNS服务器上针对单个域名配置多个IP地址的解析，当DNS解析请求到达DNS服务器时，DNS服务器将基于调度策略发出域名映射的其中一个IP地址。本地DNS服务器会缓存该IP地址与域名的映射关系，直到TTL超时。

    • 但是因为本地DNS服务器与客户端拥有缓存特性，极可能导致后端服务器之间的负载不均衡。若将TTL值调小就会导致DNS查询流量增加，DNS服务器成为流量瓶颈。如果TTL值调大就会导致动态负载不平衡，出现某些后端服务器接收到的请求较多，其他服务器几乎没有请求。

    • 另外，DNS本身没有任何的健康检查机制若后端服务器节点发生故障，DNS依旧将地址映射给用户，当用户发送请求到后端服务器时请求会失败。

    • 基于负载均衡器的负载均衡集群：

    • 该负载均衡集群需要额外部署一台负载均衡器，用户只知道如何访问负载均衡器并不知道后端真实服务器的地址与位置。负载均衡器负责将客户端发送的请求根据负载均衡算法调度到后端真实服务器。与DNS相比此种方式调度更好、更均衡。即使一台或多台后端真实服务器出现故障，负载均衡器也可以及时感知到并将请求调度到正常工作的服务器上，保持服务正常运行。

    LVS与Nginx对比：

    • LVS比Nginx具有更强的负载能力，性能更高、对内存和CPU资源消耗较低。
    • LVS工作在网络层，流量的调度由操作系统内核进行处理。Nginx可以4\7实现负载均衡，可针对HTTP应用实施分流策略。

    1.3.LVS的组成及作用

    1.3.1.组件
    1. IPVS(IP Virtual Server)：LVS是基于内核态的netfilter框架实现的IPVS功能，用于实现传输层（L4）负载均衡，支持TCP/UDP协议、支持多种调度算法和工作模式。IPVS会根据用户指定的规则对数据包进行不同的转发处理，还可以修改数据包中的内容。
    2. ipvsadm：用户空间工具，用于配置和管理IPVS，类似于iptables。用户通过ipvsadm将配置传输到内核态中的IPVS中。
    1.3.2.名词介绍

    1. RS：后端真实服务器。
    2. DS：LVS负载均衡器。
    3. VIP：虚拟IP地址（浮动IP或业务IP），用户访问的IP地址。
    4. DIP：负载均衡器与后端真实服务器通信时使用的IP地址。
    5. CIP：客户端的IP地址。
    6. RIP：RealServerIP后端真实服务器与DS通信的地址。
    7. CMAC：客户端MAC地址。
    8. VMAC：DS的VIP对应的MAC地址。
    9. DMAC：DS与RS通信的MAC地址。
    10. RMAC：RS与DS通信的MAC地址。

    LVS的整体架构主要包括负载均衡器(Load Balancer)、后端服务器(Real Server)和客户端。

    客户端的请求首先到达负载均衡器的VIP，负载均衡器根据预先配置好的负载均衡算法和后端服务器列表将请求报文转发至指定后端服务器。

    1.4.LVS基本原理

    1.4.1.netfilter基本原理

    Netfilter是Linux内核的网络包过滤框架，是iptables、nftables、firewalld等工具的基础。核心功能：

    • 数据包过滤。
    • 网络地址转换。
    • 数据包修改。
    • 连接跟踪。

    Netfilter是内核态的Linux防火墙机制，其提供了一系列钩子hook：

    • NF_IP_PRE_ROUTING：数据包进入网络栈后立即触发 DNAT
    • NF_IP_LOCAL_IN：目标是本机的数据包
    • NF_IP_FORWARD：需要转发的数据包
    • NF_IP_LOCAL_OUT：本地进程产生的出站数据包
    • NF_IP_POST_ROUTING：数据包即将离开网络栈时

    当数据包通过网络接口接入到系统时先匹配到PREROUTING链检查是否有规则，然后根据数据包的目标IP地址查找路由，若目标IP是本机IP地址，数据包会遇到INPUT链查找规则。若目标IP非本机IP地址，则触碰到FORWARD链并查找规则，最后通过POSTROUTING链送出网络接口。

    当本机始发发送数据包，该数据包先遇到OUTPUT链进行规则检查，最后通过POSTROUTING链发送出网络接口。

    1.4.2.LVS工作原理：
    1. 数据包进入系统后，查看PREROUTING链是否有配置匹配。
    2. 通过路由表查看该数据包是否访问本机，若访问本机进入INPUT链。
    3. 在INPUT链中查看数据包是否匹配到IPVS服务，若不匹配交给本地应用处理。
    4. 若匹配执行负载均衡算法，从后端真实服务器池中选择一台，计算出后端服务器的地址和端口。
    5. 在POSTROUTING链修改数据包并转发到真实服务器。

    INPUT负责决策，POSTROUTING负责修改。

    1.4.3.LVS的工作模式

    LVS中有三种工作模式：NAT、直连路由DR、TUN隧道。

    1.4.3.1.NAT模式

    NAT网络地址转换，该技术通过转换数据包中的源地址或目的地址实现私网访问公网或公网访问私网。

    1. 客户端向LVS调度器发送请求报文。（CIP --> VIP）
    2. 调度器根据负载均衡算法和后端服务器列表决定转发至哪一台后端服务器。
    3. 调度器将数据包中的目标IP和端口修改为指定后端服务器的IP与端口。目的地址从VIP修改为RIP。
    4. 后端服务器处理完该请求后，将响应报文交给调度器（网关），此时数据包源地址为RIP，目的地址为CIP。
    5. LVS调度器收到响应数据报文后，将该报文的源地址修改为VIP并根据路由转发至客户端。

    LVS调度器都是根据上文中提到的input链中的ip_vs_in函数决定报文是否触发负载均衡，且要如何修改数据报文。在NAT模式中调度器必须是后端服务器的网关，请求和响应的报文都要通过调度器进行修改。

    缺点：

    由于后端真实服务器的网关必须是负载均衡器，所以请求和响应的流量都必须经过负载均衡器，当后端服务器数量或请求量较多时会导致负载均衡器成为流量瓶颈。所以，NAT模式能够支持的后端服务器数量较少。

    1.4.3.2.DR模式

    DR直连路由模式响应数据不经过LVS，性能更高、对数据包修改小。但是负载均衡器和后端服务器必须在一个局域网，配置上会更复杂且不支持端口映射。

    1. 当客户端发送请求到达负载均衡器时，这时到达LVS网卡的数据包括：源IP地址、目的IP地址（VIP）、源MAC地址、目标MAC地址（VMAC，VIP对应的MAC地址）。
    2. 数据包到达网卡后，先经过PREROUTING链进行路由查询，发现目的IP是VIP时，这是就会发送至INPUT链。
    3. 数据包进入INPUT链后，LVS会根据数据包的目标IP和端口确认是否为LVS预定义的配置。如果是根据负载均衡算法从后端服务器列表中选择指定后端服务器。查询路由条目决定从哪个接口发出，将数据包转发至OUTPUT链。
    4. 最终数据包会被转发至POSTROUTING链，根据配置将数据包的目的MAC地址修改为RMAC（后端真实服务器的MAC地址），源MAC修改为LVS与RS同网段的MAC地址(DMAC)，修改后数据包被转发至后端服务器。
    5. 数据包到达后端服务器后，发现报文的目的MAC地址与自己网卡一致则接收该报文。处理完成后，将响应报文通过lo接口转发给物理网卡向外发出。此时该报文的源IP地址为VIP，目标IP为CIP，源MMAC为后端服务器的RMAC，目的MAC地址为网关的MAC地址。最终数据包通过后端服务器直连路由器转发给客户端。

    1.4.3.3.TUN模式

    隧道模式利用网络隧道技术，将初始IP报文头部隐藏，利用外层IP头部实现跨网络传输至后端服务器，后端服务器拆除隧道后通过本地网络将响应转发至客户端。

    隧道模式可实现负载均衡器和后端服务器跨网段、机房、区域搭建。响应报文不经过负载均衡器减少压力。但是不支持端口映射。

    1. 客户端通过网络发送请求数据包给负载均衡器的网卡，该数据包源地址为CIP、目标地址为VIP。
    2. 数据包进入PREROUTING链后，根据目的IP查找路由，确认是否为本机IP。若是数据包转发至INPUT链，根据负载均衡算法和后端服务器列表确认其转发的目的地。
    3. 该数据包进入POSTROUTING链后，为该数据包再封装一层IP头部，源IP是DIP、目标IP是RIP。
    4. 数据包转发至后端服务器后，根据目的IP发现是访问本机，拆除外层IP头部，分析内层IP头部，其目的IP是真实服务器的lo接口（VIP）。后端服务器处理完成后直接向CIP发送响应报文。

    1.4.4.负载均衡算法

    轮询(Round Robin)：将收到的请求按照顺序轮流分配给后端服务器，不管服务器实际的连接数量和系统负载。

    加权轮询（Weighted Round Robin）：根据后端服务器的处理能力分配权重，负载均衡器会根据权重分配请求至后端服务器。

    最少连接（Least Connections）：根据后端服务器已经建立的连接数进行分配，将请求优先分配给连接数少的节点。负载均衡效果更好。

    加权最少连接（Weighted Least Connections）：服务器节点的性能差异较大的情况下，可以为后端服务器调整权重，权重较高的节点将承担更大的活动连接负载。

    目标地址哈希算法（DH）：该算法是根据目标IP地址通过HASH函数，将目标IP与后端服务器建立映射关系。

    源地址哈希算法（SH）：根据客户端源地址通过HASH函数，将源IP与后端服务器建立映射关系。

    永不排队算法（NQ）：当有空闲服务器可用时，请求会被发送到空闲服务器，而不是等待快速响应的服务器。

    1.5.ipvsadm命令介绍

    基本语法：

    ipvsadm [选项] [参数]

ipvsadm -<操作> -<协议> <虚拟服务器> -s <调度算法>
         -<操作> -<协议> <虚拟服务器> -r <真实服务器> -<转发模式> -w <权重>
    1.5.1.虚拟服务器管理

    添加虚拟服务器：

    # TCP服务
ipvsadm -A -t 192.168.80.100:80 -s rr
# -A: Add virtual server
# -t: TCP协议 (VIP:Port)
# -s: 调度算法 (rr=轮询)

# UDP服务
ipvsadm -A -u 192.168.80.100:53 -s wlc

# 防火墙标记
ipvsadm -A -f 1 -s rr

    修改虚拟服务器：

    # 修改调度算法
ipvsadm -E -t 192.168.80.100:80 -s wlc
# -E: Edit virtual server

    删除虚拟服务器：

    # 删除指定虚拟服务器
ipvsadm -D -t 192.168.80.100:80
# -D: Delete virtual server
    1.5.2.真实服务器管理

    添加真实服务器：

    # 您的配置示例：
ipvsadm -a -t 192.168.80.100:80 -r 192.168.80.101:80 -g
# -a: Add real server
# -t: 虚拟服务器 (VIP:Port)
# -r: 真实服务器 (RIP:Port)
# -g: DR模式 (Gatewaying)

# 不同转发模式：
ipvsadm -a -t VIP:80 -r RIP:80 -g    # DR模式
ipvsadm -a -t VIP:80 -r RIP:80 -m    # NAT模式
ipvsadm -a -t VIP:80 -r RIP:80 -i    # TUN模式

    删除真实服务器：

    ipvsadm -d -t 192.168.80.100:80 -r 192.168.80.101:80
# -d: Delete real server
    1.5.3.调度算法
    # 轮询
ipvsadm -A -t VIP:80 -s rr

# 加权轮询
ipvsadm -A -t VIP:80 -s wrr

# 最少连接
ipvsadm -A -t VIP:80 -s lc

# 加权最少连接
ipvsadm -A -t VIP:80 -s wlc

# 源地址哈希
ipvsadm -A -t VIP:80 -s sh

# 目标地址哈希
ipvsadm -A -t VIP:80 -s dh
    1.5.4.查看和监控
    # 基本查看
ipvsadm -L
ipvsadm -Ln  # 数字格式显示

# 查看统计信息
ipvsadm -L --stats
# 输出：
# Conns: 连接数
# InPkts: 入向包数
# OutPkts: 出向包数
# InBytes: 入向字节
# OutBytes: 出向字节

# 查看速率
ipvsadm -L --rate

# 查看连接状态
ipvsadm -L -c
ipvsadm -L --connection

    详细输出示例：

    # 您的配置类似这样：
# 虚拟服务器
# Prot LocalAddress:Port Scheduler Flags
#   -> RemoteAddress:Port           Forward Weight ActiveConn InActConn
# TCP  192.168.80.100:80 rr
#   -> 192.168.80.101:80            Route   1      0          0
#   -> 192.168.80.102:80            Route   1      1          0
    1.5.5.保存和恢复配置

    保存配置：

    # 保存到文件
ipvsadm-save > /etc/sysconfig/ipvsadm
# 或
service ipvsadm save  # 某些系统

# 查看保存的配置
cat /etc/sysconfig/ipvsadm

    恢复配置：

    # 从文件恢复
ipvsadm-restore < /etc/sysconfig/ipvsadm
# 或
service ipvsadm start

    清空配置：

    # 清空所有规则
ipvsadm -C

    2.LVS实操演示

    2.1.NAT模式演示

    2.1.1.实验规划

    后端部署两台Apache服务器提供HTTP服务，通过LVS轮询算法实现负载均衡。

    负载均衡器和后端服务器的网卡使用VMnet8 192.168.80.0/24，负载均衡器和客户端使用VMnet1 192.168.10.0/24。

    1. LVS作为后端服务器的网关，需要开启IP转发功能。
    2. 所有服务器关闭防火墙和SELinux。
    3. client不需要将LVS设置为自己的网关，能够与VIP通信即可。
    2.1.2.基础配置
    1. 在后端服务器部署apache：
    [root@Apache1 ~]# yum install httpd -y

[root@Apache2 ~]# yum install httpd -y

[root@Apache1 ~]# echo "this is apache1" > /var/www/html/index.html

[root@Apache1 ~]# systemctl start httpd

[root@Apache2 ~]# echo "this is apache2" > /var/www/html/index.html

[root@Apache2 ~]# systemctl start httpd
    1. 将后端服务器的网关设置为192.168.80.100：
    [root@Apache1 ~]# ip route
default via 192.168.80.100 dev ens33 proto static metric 102
192.168.10.0/24 dev ens34 proto kernel scope link src 192.168.10.101 metric 101
192.168.80.0/24 dev ens33 proto kernel scope link src 192.168.80.101 metric 102

[root@Apache2 ~]# ip route
default via 192.168.80.100 dev ens33 proto static metric 102
192.168.10.0/24 dev ens34 proto kernel scope link src 192.168.10.102 metric 101
192.168.80.0/24 dev ens33 proto kernel scope link src 192.168.80.102 metric 102
    1. 负载均衡器开启IP路由转发：
    ### 临时开启
[root@LVS ~]# sysctl -w net.ipv4.ip_forward=1
net.ipv4.ip_forward = 1

### 永久开启
[root@LVS ~]# cat /etc/sysctl.conf | grep ip_forward
net.ipv4.ip_forward=1
[root@LVS ~]# sysctl -p
    1. 测试后端服务器HTTP：
    [root@LVS ~]# curl 192.168.80.101
this is apache1

[root@LVS ~]# curl 192.168.80.102
this is apache2
    2.1.3.LVS配置
    1. 安装ipvsadm：
    [root@LVS ~]# yum install ipvsadm -y
    1. 配置LVS：
    ### 在IPVS中创建一个虚拟服务，VIP是192.168.10.100，端口80，使用轮询算法
[root@LVS ~]# ipvsadm -A -t 192.168.10.100:80 -s rr

### 向刚才创建192.168.10.100:80这个虚拟服务中添加后端服务器，并使用NAT模式
[root@LVS ~]# ipvsadm -a -t 192.168.10.100:80 -r 192.168.80.101:80 -m

[root@LVS ~]# ipvsadm -a -t 192.168.10.100:80 -r 192.168.80.102:80 -m

    2.2.DR模式演示

    2.2.1.实验规划

    后端部署两台Apache服务器提供HTTP服务，通过LVS轮询算法实现负载均衡。

    增加一台路由器作为VMnet1 192.168.10.0/24和VMnet8 192.168.80.0/24的网关。

    • 所有服务器关闭防火墙和SELinux。

    该实验在上个实验基础上修改。

    2.2.2.基础配置

    1. 在Gateway上修改地址为192.168.10.254\192.168.80.254

    2. 在Gateway开启IP转发功能

    [root@Gateway ~]# cat /etc/sysctl.conf | grep ip_forward
net.ipv4.ip_forward=1
[root@Gateway ~]# sysctl -p
    1. 修改LVS和后端服务器的网关，关闭LVS的VMnet1网卡

    1. 配置客户端IP与网关
    2. 测试客户端与后端服务器通信
    [root@client ~]# curl 192.168.80.101
this is apache1

[root@client ~]# curl 192.168.80.102
this is apache2
    2.2.3.LVS配置
    1. 在后端服务器上添加回环口VIP：
    [root@Apache1 ~]# ip addr add  192.168.80.100/32 dev lo:0

[root@Apache2 ~]# ip addr add  192.168.80.100/32 dev lo:0
    1. 在后端真实服务器上配置
    [root@Apache2 ~]# vim /etc/sysctl.conf
net.ipv4.conf.all.arp_ignore = 1
net.ipv4.conf.all.arp_announce = 2
net.ipv4.conf.lo.arp_ignore = 1
net.ipv4.conf.lo.arp_announce = 2
### arp_ignore 用于控制是否响应ARP请求，0代表响应所有接口的所有ARP请求，1代表只响应目标IP是本机接口IP的ARP请求，2代表只响应目标IP是本机接口IP且查询这IP在同一子网的ARP请求。
在这里是为了保证后端服务器不会响应针对VIP的ARP请求。
### arp_announce 用于控制发送ARP响应时使用的源IP地址，0使用任意接口的地址，1尽量避免使用不属于发送接口子网的地址，3总是使用最适合目标网络的本地地址
这是为了保证后端服务器响应客户端时使用VIP作为源地址

[root@Apache2 ~]# sysctl -p
    1. 配置LVS
    [root@LVS ~]# ipvsadm -A -t 192.168.80.100:80 -s rr

[root@LVS ~]# ipvsadm -a -t 192.168.80.100:80 -r 192.168.80.101:80 -g

[root@LVS ~]# ipvsadm -a -t 192.168.80.100:80 -r 192.168.80.102:80 -g
    2.2.4.测试
    [root@client ~]# curl 192.168.80.100
this is apache2

[root@client ~]# curl 192.168.80.100
this is apache1

    2.3.TUN模式演示

    2.2.1.实验规划

    后端部署两台Apache服务器提供HTTP服务，通过LVS轮询算法实现负载均衡。

    这个实验有一个需要注意的地方，包含VIP的数据包不能在路由器的多个接口中出现，会导致路由器的ARP表混乱。在实际的场景中使用TUN模式的场景一般真实服务器与调度器的间隔比较远，不太可能会遇到这个问题，但咱们做实验的时候要规避这个问题。

    所以，我的实验规划是使用两张网卡VMnet1 192.168.10.0/24和VMnet8 192.168.80.0/24。

    • 路由器：192.168.10.254,192.168.80.254。
    • LVS：物理接口192.168.80.200/24、tunl0 192.168.80.100/32。

    • 后端服务器：物理接口192.168.10.101,192.168.10.102、tunl0 192.168.80.100/32

    • 所有服务器关闭防火墙和SELinux。

    2.2.2.基础配置
    1. 安装ipvsadm：
    [root@LVS ~]# yum install ipvsadm -y
    1. 设置LVS的IP地址与网关并关闭VMnet1网卡：

    1. 部署后端服务器HTTP：

    2.2.3.LVS配置
    1. 在LVS上启用IPIP隧道
    [root@LVS ~]# modprobe ipip

[root@LVS ~]# lsmod | grep ipip
ipip                   16384  0
tunnel4                16384  1 ipip
ip_tunnel              36864  1 ipip
    1. 在LVS上创建隧道接口配置地址
    [root@LVS ~]# ip addr add 192.168.80.100/32 dev tunl0

[root@LVS ~]# ip link set up tunl0
    1. 在后端服务器上创建隧道接口并配置地址
    [root@Apache1 ~]# modprobe ipip

[root@Apache1 ~]# ip addr add 192.168.80.100/32 dev tunl0

[root@Apache1 ~]# ip link set up tunl0

[root@Apache2 ~]# modprobe ipip

[root@Apache2 ~]# ip addr add 192.168.80.100/32 dev tunl0

[root@Apache2 ~]# ip link set up tunl0
    1. 在LVS上配置内核参数（可选）
    # 启用IP转发
echo 1 > /proc/sys/net/ipv4/ip_forward

# 禁用反向路径过滤
echo 0 > /proc/sys/net/ipv4/conf/all/rp_filter
echo 0 > /proc/sys/net/ipv4/conf/tunl0/rp_filter

# 配置ARP参数
echo 1 > /proc/sys/net/ipv4/conf/all/arp_ignore
echo 2 > /proc/sys/net/ipv4/conf/all/arp_announce
echo 1 > /proc/sys/net/ipv4/conf/tunl0/arp_ignore
echo 2 > /proc/sys/net/ipv4/conf/tunl0/arp_announce
    1. 在LVS上配置IPVS规则：
    [root@LVS ~]# ipvsadm -A -t 192.168.80.100:80 -s rr
[root@LVS ~]# ipvsadm -a -t 192.168.80.100:80 -r 192.168.20.101:80 -i
[root@LVS ~]# ipvsadm -a -t 192.168.80.100:80 -r 192.168.20.102:80 -i
    1. 在后端真实服务器上配置：
    [root@Apache1 ~]# vim /etc/sysctl.conf
net.ipv4.conf.all.rp_filter=0
net.ipv4.conf.default.rp_filter=0
net.ipv4.conf.ens33.rp_filter=0
net.ipv4.conf.tunl0.rp_filter=0
### rp_filter是Linux内核的一个安全机制，用于防止IP地址欺骗攻击。它会检查进入网络接口的数据包，验证其源IP地址是否可以通过接收这个数据包的网络接口返回。
### 由于后端真实服务器接收的端口是tunl0接口，所以需要关闭该检查。
[root@Apache1 ~]# sysctl -p
    1. Gateway上配置ARP（看情况）
    [root@Gateway ~]# arp -s 192.168.80.100 00:0c:29:71:a0:54
    2.2.4.验证
    [root@client ~]# curl http://192.168.80.100
this is Apache2
[root@client ~]# curl http://192.168.80.100
this is Apache1
