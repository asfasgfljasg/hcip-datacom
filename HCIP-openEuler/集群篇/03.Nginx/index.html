    03.Nginx

    1.基础原理

    1.1.Nginx是什么？

    Nginx(engine x)是高性能HTTP和反向代理web服务器，同时也提供IMAP/POP3/SMTP等邮件代理功能。Nginx是由伊戈尔·赛索耶夫为俄罗斯访问量第二的Rambler.ru站点（俄文：Рамблер）开发的，第一个公开版本0.1.0发布于2004年10月4日。其将源代码以类BSD许可证的形式发布，因它的稳定性、丰富的功能集、简单的配置文件和低系统资源的消耗而闻名。2011年6月1日，nginx 1.0.4发布。

    Nginx负载均衡是通过服务器充当反向代理服务器来实现的（负载均衡功能依赖于反向代理）。Nginx充当负载均衡器时接收客户端请求，根据预定义的负载均衡算法与后端服务器列表，将请求分发到指定后端服务器上。

    Nginx的负载均衡功能具有高效、灵活、易于配置的特点，并且支持多种负载均衡算法和健康检查机制。另外，Nginx的负载均衡支持L7和L4，一段会话的请求与回复都需要经过Nginx，所以其支持端口映射。

    1.2.工作原理

    1.2.1.反向代理

    反向代理是客户端请求的中间人，它负责接收客户端的请求，然后将请求转发到后端服务器，最后将服务器的响应返回给客户端。所以，反向代理是为后端服务器提供的。

    工作过程：

    1. 客户端浏览器输入URL经过DNS解析获取反向代理服务器的IP地址，随后向反向代理服务器发起HTTP请求。

    2. 反向代理服务器解析客户端发送的HTTP请求，根据该请求中的URL与自身的配置文件决定是否转发到后端服务器。

    3. Nginx与后端服务器建立一个新的、独立的TCP连接。

    4. Nginx重新构建并转发请求，新的请求中可能包含原始请求的Host、客户端真实IP、代理信息等。

    5. 若Nginx配置了缓存，会先检查是否有可用的缓存副本。如果没有或缓存过期才执行上一步。

    6. 后端服务器接收到请求后，根据配置生成HTTP响应返回给Nginx。

    7. Nginx会将后端服务器的响应放置到缓冲区，然后立刻关闭与后端服务器的连接，同时不紧不慢将响应给到客户端。（缓冲）这是为了提升性能不占用与后端服务器的连接。

    特点：

    • 隐藏后端服务器：客户端不知道真实服务器的存在。
    • SSL终止：可以在Nginx上处理HTTPS，减轻后端压力。
    • 缓存静态内容：加快响应速度。
    • 安全防护：作为额外的安全层。
    • URL重新：可修改请求路径。
    • 端口映射：前后端端口可以不一致。
    1.2.2.正向代理

    正向代理和反向代理有明显的不同点。反向代理实际上是为服务端提供服务的，而正向代理是为客户端提供服务的。客户端主动指定代理服务器，代理服务器根据客户端请求，动态解析目标地址。代理服务器隐藏了客户端的真实IP，目标服务器只能看到代理服务器的IP。所以，正向代理是客户端访问边界的延申。

    工作过程：

    1. 客户端将请求发往代理服务器。
    2. 代理服务器转发请求到达目标服务器。
    3. 目标服务器返回响应给代理服务器。
    4. 代理服务器将响应返回给客户端。

    看似好像和反向代理相同，但是反向代理它再转发的时候是根据配置文件中预设的后端服务器地址进行转发。而正向代理是动态的根据客户端发送的请求中Host和URI字段进行转发的。所以，正向代理是主动的，反向代理是被动的。正向代理为客户端服务，目标动态决定。反向代理为服务器服务，目标预先固定的。

    1.2.3.负载均衡

    负载均衡也是在反向代理上的一种扩展，提供了一种廉价有效的方法扩展网络设备和服务器的带宽、增加吞吐量、加强服务器请求处理能力和冗余性。

    负载均衡的意思是将大量请求分摊到多台后端服务器上进行处理，从而整体提升业务处理能力。负载均衡可以针对多种服务进行集群搭建，例如：HTTP、FTP、MAIL等。

    简单来说，公司原本采用一台服务器处理HTTP业务，随着公司发展业务量增大原本的服务器已经无法胜任现在的工作。你现在有两个选择：升级当前服务器的硬件或增加多台服务器组成集群一起提供HTTP服务。很显然单台服务器即使预算再多，终究双拳难敌四手，增加服务器数量更灵活、成本更低。

    但服务器数量增多了，怎么能够让请求流量均匀分布到后端所有服务器上，防止出现一部分服务器请求较少另一部分服务器请求过多的问题？

    1.2.4.动静分离

    Nginx的静态资源处理能力很强，但是动态资源资源处理能力不足，可以采用动静分离方式弥补。动静分离实际是采用代理的方式配合location实现。通过location实现静态资源由Nginx自身处理，而动态资源交由PHP-FPM或后端服务器进行处理。

    2.配置演示

    2.1.反向代理实验

    2.1.1.实验规划

    后端服务器部署Apache提供HTTP服务，当客户端访问http://192.168.80.100/openeuler时，将请求代理到后端服务器http://192.168.80.101。

    2.1.2.后端服务器配置
    [root@Apache ~]# yum install httpd -y

[root@Apache ~]# echo "This is Apache" > /var/www/html/index.html

[root@Apache ~]# systemctl start httpd
    2.1.3.Nginx反向代理配置
    [root@Nginx ~]# yum install -y nginx

[root@Nginx ~]# vim /etc/nginx/nginx.conf
    server {
        location /openeuler/  {
                proxy_pass http://192.168.80.101/;
                }
    }

[root@Nginx ~]# systemctl restart nginx
    2.1.4.测试
    C:\Users\Administrator>curl http://192.168.80.100/openeuler/
This is Apache

    从抓包的现象能够看出：

    1. 客户端与Nginx建立TCP连接。发送请求至192.168.80.100，URI为openeuler。
    2. Nginx收到该请求后，紧接着向后端服务器建立TCP连接，并将请求转发至后端服务器。
    3. 后端服务器处理完请求后回复响应给Nginx，并拆除TCP连接。
    4. Nginx将该响应转发至客户端，关闭TCP连接。
    2.1.5.显示真实客户端IP

    现象：在后端服务器上查看访问日志，客户端地址显示为Nginx，而并非客户端的实际IP。这是因为代理是单独向后端服务器开启新的会话，且默认没有修改访问头部。

    [root@Apache ~]# cat /var/log/httpd/access_log
192.168.80.100 - - [18/Dec/2025:14:36:19 +0800] "GET / HTTP/1.0" 200 15 "-" "curl/8.16.0"
192.168.80.100 - - [18/Dec/2025:14:36:32 +0800] "GET / HTTP/1.0" 200 15 "-" "curl/8.16.0"

    传递真实IP地址的需求如下：

    1. 日志记录和分析：真实 IP 地址对于日志分析和用户行为追踪至关重要。如果使用代理服务器的 IP 地址，所有请求看起来都来自同一来源，这会导致分析结果不准确。
    2. 安全和访问控制：基于 IP 地址的访问控制策略需要识别真实的客户端 IP 地址。如果只看到代理服务器的 IP 地址，访问控制策略将无法正确应用。
    3. 地理位置追踪：很多服务依赖于客户端的地理位置信息，而这些信息通常是基于 IP 地址进行的。如果无法获取到真实的客户端 IP 地址，地理位置服务将无法正常工作。

    解决方法：

    最常用的方法是通过X-Forwarded-For头部传递客户端的真实IP地址。Nginx可以在代理转发请求时添加这个头，以便后端服务器能够获取到真实客户端的IP地址。

    Nginx配置：

    location /openeuler/  {
        proxy_pass http://192.168.80.101/;
        proxy_set_header Host $host;    # 将客户端原始请求的Host头部传递给后端服务器
        proxy_set_header X-Real-IP $remote_addr;    # 传递客户端的真实IP地址
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;    # 记录整个代理链的IP路径，中间如果还有其他代理，也会一并记录
        proxy_set_header X-Forwarded-Proto $scheme; # 传递客户端使用的原始协议（HTTP或HTTPS）
        }

    Apache配置：

    # 在httpd.conf或apache2.conf中添加：
LogFormat "%{X-Forwarded-For}i %l %u %t \"%r\" %>s %b \"%{Referer}i\" \"%{User-Agent}i\"" proxy # 使用整个X-Forwarded-For代理链的地址
CustomLog logs/access_log proxy

    2.1.9.被动健康检测

    Nginx的主动健康检测是商业版才能够使用的，开源版本通过YUM下载的只能使用被动健康检测。但是也可以通过源码安装方式添加nginx_upstream_check_module模块。

    Nginx默认就已经开启了被动健康检测，即使你不配置任何健康检测参数，也有基本的被动健康检测：

    upstream backend {
    # 默认就有被动健康检测
    server 192.168.1.100:8080;
    server 192.168.1.101:8080;

    # 等价于：
    server 192.168.1.100:8080 max_fails=1 fail_timeout=10s;
    server 192.168.1.101:8080 max_fails=1 fail_timeout=10s;
}

    • max_fails = 1：1次失败就标记为不可用

    • fail_timeout = 10s：失败后暂停10秒

    工作原理：

    客户端请求 → Nginx → 后端服务器
         ↓
    请求失败（超时、连接拒绝等）
         ↓
    fail_timeout计数器+1
         ↓
    fail_timeout计数器 >= max_fails ?
         ↓
     是 → 标记服务器为"不可用"
         ↓
    fail_timeout秒后自动恢复

    失败触发条件：

    1. 连接超时
    2. 连接被拒绝
    3. 读取超时
    4. 无效的HTTP响应
    5. 代理返回特定状态码

    备用服务器：

    upstream openeuler {
        server 192.168.80.101:8080 backup;
        server 192.168.80.102:80;
}

    将Apache1设置为备用，正常情况下流量都会被调度到Apache2。当Apache2出现故障后，Nginx会将流量调度到Apache1备用服务器上。

    2.3.1.实验规划

    后端服务器部署两台Apache：192.168.80.101:8080,192.168.80.102。

    当客户端访问192.168.80.100:81时，将请求根据负载均衡算法转发至后端。

    2.3.2.Nginx配置

    Nginx L4的负载均衡配置需要用到stream块，该配置块与HTTP配置开同级别。所以就不能再使用虚拟主机的方式去配置了。

    [root@Nginx ~]# vim /etc/nginx/nginx.conf
    stream {
            upstream openeuler {
                    server 192.168.80.101:8080;
                    server 192.168.80.102:80;
            }
            server {
                    listen 82;
                    proxy_pass openeuler;
            }
    }

[root@Nginx ~]# systemctl restart nginx

    测试：

    C:\Users\Administrator>curl http://192.168.80.100:82
This is Apache2

C:\Users\Administrator>curl http://192.168.80.100:82
This is Apache1

C:\Users\Administrator>curl http://192.168.80.100:82
This is Apache2

C:\Users\Administrator>curl http://192.168.80.100:82
This is Apache1

    从抓包现象能够看出L4的负载均衡与反向代理的工作原理是一样的。

    2.4.3.配置Nginx主配置文件
    [root@Nginx ~]# vim /usr/local/nginx/conf/nginx.conf
upstream openeuler {
        server 192.168.80.101:80;
        server 192.168.80.102:80;
        server 192.168.80.103:80 backup;
### 健康检查间隔为5000毫秒=5秒，连续成功两次标记为健康，连续失败三次标记为不健康，检查超时时间为1秒，协议为HTTP
        check interval=5000 rise=2 fall=3 timeout=1000 type=http;
### 检查报文发送HTTP请求，使用HEAD方法，请求根路径，HTTP1.0协议
        check_http_send "HEAD / HTTP/1.0\r\n\r\n";
### 期望得到的状态码为2XX和3XX
        check_http_expect_alive http_2xx http_3xx;
        }
server {
    location /status {
            check_status;
            access_log off;
    }
    location /openeuler/ {
            proxy_pass http://openeuler/;
    }
}
[root@Nginx ~]# nginx 
[root@Nginx ~]# nginx -s reload
