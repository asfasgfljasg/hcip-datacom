    DNS

    概述

    DNS（Domain Name System），DNS域名解析服务，最核心的功能是将域名解析为IP地址。因为互联网上的各种访问都需要通过IP地址进行，用户很难直接通过IP地址的方式访问连接，所以就有了DNS。用户想要访问连接时，只需要输入域名，域名相对IP地址来说更好记忆。

    Windows系统判断网络是否正常时，就需要使用到DNS的检测。当开启网卡后，Windows会发送对 www.msftncsi.com 的DNS查询，如果查询失败，则说明此Windows无法正常进行域名解析，通常此时网卡会呈现黄色感叹号。

    DNS采用C/S（客户端/服务器）架构，监听在 UDP/TCP 53 端口：

    • UDP 53：这是DNS最常用的端口。大多数情况下，DNS 查询和响应使用 UDP 协议通过端口 53 进行通信。因为 UDP 协议开销较小，效率较高，适用于大多数简单的域名查询。
    • TCP 53：当DNS的数据包长度超过UDP最大长度（512字节）和响应数据量较大或者区域查询时（DNS服务器之间同步数据），会使用TCP 53通信。

    域名服务器结构

    DNS服务器通常采用分布式的多层架构，主要包括以下几个层次：

    1. 根域名服务器

    • 用 . 表示根域是 DNS 层次结构的最顶层，负责管理顶级域名（如 .com、.org、.net 等）的 DNS 信息。全球共有 13 组根域名服务器，它们的地址是固定的。根域名服务器中只保存了顶级域名服务器的信息。
    • 当查询一个未知的顶级域名时，首先会向根域名服务器发起请求。
    • Linux中的 /var/named/named.ca 文件中，记录了13台根域名服务器的IP地址。

    2. 顶级域名服务器

    • 负责管理各自顶级域名服务器中所属的权威域的DNS 信息。顶级域名服务器只保存对应权威DNS服务器的信息。顶级域名服务器一般情况下，只提供权威域名服务器的信息。

    3. 权威域名服务器

    • 负责保存并提供该域名及其子域名的 DNS 记录。
    • 权威域名服务器是真正管理并回应DNS记录的服务器。

    4. 本地 DNS 服务器

    • 通常由网络服务提供商（ISP）提供，是用户计算机首先接触的 DNS 服务器。
    • 它会缓存之前查询过的 DNS 记录，以提高查询效率。当本地 DNS 服务器没有所需的 DNS 记录时，会按照层次结构向上级服务器发起查询。
    • 在家中或公司内，通常由家庭路由器或企业网络管理员分配的，DHCP的方式自动下发到我们的电脑中。
    • 我们也可以手动指定DNS服务器的地址，例如 114.114.114.114，这时我们就使用公共DNS服务器代替了本地DNS服务器。

    域名结构

    域名结构是分层的，从右到左，依次为顶级域名、二级域名、子域名等，具有层次化和易于管理的特点。

    常见的域名结构示例： www.example.com.

    • . 是根域名
    • .com 是顶级域名（Top-Level Domain，TLD）
    • example 是二级域名（Second-Level Domain，SLD），由域名所有者自行定义，通常反映了网站或组织的名称
    • www 是子域名（Subdomain），它是二级域名的细分（三级域名），用于区分同一域名下的不同服务或功能。例如，mail.example.com 可能用于指向邮件服务，blog.example.com 可能用于指向博客页面
    • 还可以有更多层级子域名

    常见的顶级域名以及用途

    顶级域名 用途
    .com 商业用途，适用于各类公司和企业
    .org 通常用于非营利组织
    .net 常用于网络服务提供商
    .gov 政府机构专用
    .edu 教育机构使用
    .info 提供信息服务的网站
    .biz 商业用途，尤其适用于中小企业
    .name 个人域名
    .mobi 专门用于手机等移动设备的网站
    .pro 适用于专业人士，如医生、律师等
    .co 常用于公司或商业目的，在某些国家较为流行
    .cn 是中国的国家顶级域名，代表中国。适用于在中国境内注册和运营的各类组织和个人，包括企业、政府机构、社会团体、个人等，以展示其在中国的身份和业务存在

    DNS的查询方式（正向解析）

    递归查询

    递归查询中，客户端会认为自己只是通过本地DNS获取到的，对于递归查询的过程是没有感知的，不需要客户端进行参与，全程只有本地DNS服务器会进行回应。适用于网络环境比较简单的情况下。

    查询步骤：

    1. 客户端查询DNS时，首先会查找本地hosts文件是否有对应解析，如果没有解析才会向本地服务器发起解析。
    2. 本地DNS服务器会检查自己的缓存中是否有所需的记录。如果没有，则向根域名服务器发起查询。
    3. 根域名服务器返回顶级域名服务器的地址，本地DNS服务器再向顶级域名服务器查询。
    4. 顶级域名服务器返回权威域名服务器的地址，本地DNS服务器接着向权威域名服务器查询。
    5. 权威域名服务器查找记录，若有则把DNS记录返回给本地DNS服务器，若没有则告诉本地DNS服务器没有找到对应记录。
    6. 本地DNS服务器把DNS记录或是失败消息，转发给客户端，到此DNS递归查询结束。

    优点：

    • 对客户端友好：客户端无需了解复杂的 DNS 架构和查询过程，只需向本地 DNS 服务器发送请求并等待结果，使用简单方便。减少了客户端的处理负担和复杂性。

    缺点：

    • 增加本地 DNS 服务器负担：本地 DNS 服务器需要处理所有的查询步骤，可能会消耗大量的资源和时间，尤其在大量并发查询时可能会出现性能瓶颈。
    • 可能存在单点故障：如果本地 DNS 服务器出现故障，客户端的所有查询都将受到影响。
    • 潜在的安全风险：由于本地 DNS 服务器需要与多个外部服务器交互，存在受到攻击或被劫持的风险。

    迭代查询

    迭代查询中一直是由客户端介入的，向每一个层级进行查询，和递归查询的区别是，本来由本地DNS服务器干的活，都需要客户端自己干了。适用于大型企业网络或具有特殊安全和策略要求的网络环境，可更灵活地控制查询流程。

    查询步骤：

    1. 客户端查询 DNS 时，首先会查找本地 hosts 文件是否有对应解析，如果没有解析才会向本地服务器发起解析。
    2. 本地 DNS 服务器会检查自己的缓存中是否有所需的记录。如果没有，则向客户端返回根域名服务器的地址。
    3. 客户端向根域名服务器发起查询。
    4. 根域名服务器返回顶级域名服务器的地址给客户端。
    5. 客户端再向顶级域名服务器查询。
    6. 顶级域名服务器返回权威域名服务器的地址给客户端。
    7. 客户端接着向权威域名服务器查询。
    8. 权威域名服务器查找记录，若有则把 DNS 记录返回给客户端，若没有则告诉客户端没有找到对应记录。
    9. 到此 DNS 迭代查询结束。

    优点：

    • 减轻 DNS 服务器负担：本地 DNS 服务器不需要承担完整的查询工作，只需提供指引，降低了其资源消耗和工作压力，有助于在高并发情况下保持稳定性能。
    • 提高系统可扩展性：由于客户端参与了查询过程，分散了查询任务，使得整个 DNS 系统能够更好地应对大规模的查询请求，便于系统的扩展和升级。
    • 降低单点故障影响：客户端不依赖于单个本地 DNS 服务器完成所有查询，即使本地 DNS 服务器出现故障，客户端仍有可能通过其他途径获取 DNS 信息。

    缺点：

    • 对客户端要求较高：客户端需要参与查询过程，自行与多个不同层级的域名服务器进行交互，这对于一些不具备相关知识或技术能力的客户端来说可能存在困难。增加了客户端的复杂性和处理负担。
    • 响应时间可能较长：客户端需要依次向不同的服务器发起查询，每个步骤都可能引入一定的延迟，导致整体响应时间相对较长。

    结合使用递归和迭代

    在实际的 DNS 架构中，可以结合使用递归和迭代查询，常见的方式如下：

    1. 对于内部关键服务或特定域名：可以配置本地 DNS 服务器采用递归查询，以确保快速准确地获取解析结果，保证服务的稳定性和响应速度。
    2. 对于一般性的公共域名查询：本地 DNS 服务器可以先尝试在缓存中查找，如果没有，则采用迭代查询方式，引导客户端逐步向各级域名服务器获取结果。
    3. 根据网络区域划分：在不同的网络区域，根据其重要性和性能需求，灵活配置递归和迭代查询的使用策略。例如，总部网络可能更多使用递归查询，而分支机构网络部分使用迭代查询。
    4. 基于时间或流量策略：在网络负载较低的时间段或对于流量较小的查询请求，采用递归查询；在高峰时段或流量较大时，对于非关键域名的查询切换为迭代查询。
    5. 结合用户权限：根据用户的权限级别或所属部门，为不同用户的查询请求配置不同的查询方式。

    反向解析

    DNS正向解析是通过域名获取IP地址，那么反向解析就是通过IP地址获取域名的过程。

    使用场景

    1. 邮件服务器验证
    2. 帮助邮件服务器确认发送邮件的服务器是否合法，减少垃圾邮件的产生。
    3. 如果发送邮件的服务器的IP地址没有正确的反向解析记录，则被视为垃圾邮件。

    4. 例如：当你收到一封来自某个IP的邮件，通过反向解析可以确定该IP对应的域名，从而判断邮件来源的可靠性。

    5. 网络访问控制

    6. 一些网络安全策略基于IP地址的反向解析结果来决定是否允许访问。

    工作原理

    DNS 数据库中存储了正向和反向的映射信息。在反向解析中，IP 地址被反转（例如，192.168.1.1 变为 1.1.168.192），然后在特定的反向解析区域（通常称为 in-addr.arpa 域）中查找对应的域名记录。

    反向解析的配置通常由网络服务提供商（ISP）或拥有 IP 地址块的组织负责。需要在相应的 DNS 服务器上正确设置反向解析区域和记录。

    例如，假设您的服务器的 IP 地址是 123.45.67.89，在配置反向解析时，会在 89.67.45.123.in-addr.arpa 区域中创建指向您服务器域名（如 yourserver.example.com）的 PTR 记录。

    配置

    主配置文件解析 (/etc/named.conf)

    options {
    listen-on port 53 { 127.0.0.1; };
    listen-on-v6 port 53 { ::1; };
    directory          "/var/named";
    dump-file          "/var/named/data/cache_dump.db";
    statistics-file    "/var/named/data/named_stats.txt";
    memstatistics-file "/var/named/data/named_mem_stats.txt";
    secroots-file      "/var/named/data/named.secroots";
    recursing-file     "/var/named/data/named.recursing";
    allow-query        { localhost; };
    recursion yes;
    dnssec-validation yes;
    managed-keys-directory "/var/named/dynamic";
    pid-file "/run/named/named.pid";
    session-keyfile "/run/named/session.key";
    include "/etc/crypto-policies/back-ends/bind.config";
};

logging {
    channel default_debug {
        file "data/named.run";
        severity dynamic;
    };
};

zone "." IN {
    type hint;
    file "named.ca";
};

include "/etc/named.rfc1912.zones"; # 引入区域文件（正向和反向）
include "/etc/named.root.key";  # 根域列表

    options 部分：

    • listen-on port 53 { 127.0.0.1; };：指定 DNS 服务器在端口 53 上监听的地址为本地环回地址 127.0.0.1。如果改为 any，则表示在所有可用的网络接口上监听。
    • listen-on-v6 port 53 { ::1; };：指定在 IPv6 下在端口 53 上监听的地址为本地环回地址 ::1。
    • directory "/var/named";：指定 DNS 服务器的数据目录。
    • dump-file "/var/named/data/cache_dump.db";：指定缓存转储文件的路径。
    • statistics-file "/var/named/data/named_stats.txt";：指定统计信息文件的路径。
    • memstatistics-file "/var/named/data/named_mem_stats.txt";：指定内存统计信息文件的路径。
    • secroots-file "/var/named/data/named.secroots";：指定安全根文件的路径。
    • recursing-file "/var/named/data/named.recursing";：指定递归相关文件的路径。
    • allow-query { localhost; };：当前仅允许本地主机进行查询，通常更倾向于在防火墙进行此类限制。
    • recursion yes;：启用递归查询功能。
    • dnssec-validation yes;：启用 DNSSEC 验证。
    • managed-keys-directory "/var/named/dynamic";：指定管理密钥的目录。
    • pid-file "/run/named/named.pid";：指定进程 ID 文件的路径。
    • session-keyfile "/run/named/session.key";：指定会话密钥文件的路径。
    • include "/etc/crypto-policies/back-ends/bind.config";：包含指定的配置文件。

    logging 部分：

    • 定义了一个名为 default_debug 的日志通道，将日志输出到 data/named.run 文件，日志级别为动态。

    zone "." IN 部分：

    • 定义了根区域，类型为 hint，数据文件为 named.ca。

    • include "/etc/named.rfc1912.zones";：引入区域配置文件。

    • include "/etc/named.root.key";：引入根域的相关密钥文件。

    /var/named 下的文件目录的作用

    • named.ca：存放根域名服务器的地址（IPv4、IPv6）
    • named.localhost：正向区域配置文件模板
    • named.loopback：反向区域配置文件模板
    • named.empty：模板
    • slaves：用于主从
    • data：用于存放数据
    • dynamic：通常用于存放与动态 DNS 相关的信息

    /etc/named.rfc1912.zones 配置文件解析

    该文件用于定义DNS区域的相关信息，包括区域的名称、类型（如主区域、从区域、正向区域、反向区域）以及对应的区域数据文件的路径。

    例（正向区域）：

    zone "example.com" IN {          # 定义了正向区域的名字
    type master;                  # 表示这是一个主区域
    file "example.com.zone";      # 指定正向区域配置文件的位置
};

    例（反向区域）：

    zone "100.168.192.in-addr.arpa" IN {   # 反向区域，需要反写IP，并接上in-addr.arpa
    type master;
    file "192.168.100.zone";
};

    区域配置文件

    区域配置文件是 DNS 服务器中用于定义特定区域（如域名区域或反向 IP 区域）相关信息和资源记录的文件。

    正向区域配置文件

    $TTL 1D
@   IN SOA  @ rname.invalid. (
                    0          ; serial
                    1D         ; refresh
                    1H         ; retry
                    1W         ; expire
                    3H )       ; minimum
    NS      @
    A       127.0.0.1
    AAAA    ::1

    可将多个不同子网的IP进行解析，不需要写在多个正向区域文件。

    • $TTL 1D：设置默认的生存时间（Time To Live）为 1 天，当下级DNS解析到该服务器的记录后，缓存一天时间。
    • @ IN SOA @ rname.invalid. (...)：
    • @ 表示当前区域，代表此区域文件为单独的，与其他域无关系。
    • IN 表示 Internet 类别。
    • SOA 是起始授权机构记录。代表该域为权威域。
    • @ 在这里作为主域名服务器的名称。
    • rname.invalid. 是管理员的邮箱（将 @ 替换为 .）。
    • 括号内：
      • 0：版本号（serial）
      • 1D：表示从服务器向主服务器同步记录的时间间隔（refresh）
      • 1H：表示从服务器向主服务器同步记录的重试时间（retry）
      • 1W：表示从服务器判断主服务器是否失效的时间间隔（expire）
      • 3H：无效域名的缓存时间（minimum）。在这段时间内，用户查询无效域名，服务器将会直接返回无法解析，不进行查询
    • NS @：指定名称服务器为当前区域。
    • A 127.0.0.1：将当前区域解析到 IPv4 地址 127.0.0.1。
    • AAAA ::1：将当前区域解析到 IPv6 地址 ::1。

    反向区域配置文件

    $TTL 1D
@   IN SOA  @ rname.invalid. (
                    0          ; serial
                    1D         ; refresh
                    1H         ; retry
                    1W         ; expire
                    3H )       ; minimum
    NS      @
    A       127.0.0.1
    AAAA    ::1
    PTR     localhost.

    其他都和正向区域配置文件一致，只是记录是PTR记录。需要注意：==如果不同网段的反向记录，要有多个反向区域配置文件，一个反向区域配置文件，只能配置一个子网的反向记录。==

    • $TTL 1D：表示默认的生存时间（Time To Live）为 1 天。
    • @ IN SOA @ rname.invalid. (...)：
    • @ 代表当前区域。
    • IN 表示 Internet 类别。
    • SOA 是起始授权机构记录。
    • 第一个 @ 表示主域名服务器，第二个 rname.invalid. 是管理员的邮箱（将 @ 替换为 .）。括号中的数字分别表示序列号、刷新间隔、重试间隔、过期时间和最小生存时间。
    • NS @：指定名称服务器为当前区域。
    • A 127.0.0.1：将当前区域解析到 IPv4 地址 127.0.0.1。
    • AAAA ::1：将当前区域解析到 IPv6 地址 ::1。
    • PTR localhost.：创建一个指针（PTR）记录，将 IP 地址与主机名 localhost 关联。

    DNS的记录类型

    1. A 记录（Address Record）：将域名映射到 IPv4 地址。

    2. 例如：www.example.com. A 192.168.1.10 表示当用户访问 www.example.com 时，将被引导到 192.168.1.10 这个 IPv4 地址。

    3. AAAA 记录（IPv6 Address Record）：将域名映射到 IPv6 地址。

    4. 例如：www.example.com. AAAA 2001:0db8:85a3:0000:0000:8a2e:0370:7334

    5. CNAME 记录（Canonical Name Record）：为域名创建别名。

    6. 例如：alias.example.com. CNAME www.example.com. 意味着访问 alias.example.com 时，实际上会被重定向到 www.example.com。
    7. www.baidu.com 就是一个别名记录。

    1. MX 记录（Mail Exchanger Record）：指定负责接收该域电子邮件的邮件服务器。
    2. 当有邮件发送到某个域名（例如 example.com）时，邮件服务器会查询该域名的 MX 记录，以确定将邮件路由到哪个具体的邮件服务器进行处理。

    3. 例如，如果 example.com 的 MX 记录设置为 MX 10 mail.example.com，这意味着邮件应该优先发送到 mail.example.com 这个邮件服务器。数字 10 表示优先级，数值越小优先级越高。如果存在多个 MX 记录，邮件服务器会根据优先级来选择首先尝试投递邮件的服务器。

    4. NS 记录（Name Server Record）：指定负责该区域的域名服务器。

    5. 例如：example.com. NS ns1.example.com. 表明 ns1.example.com 是 example.com 区域的域名服务器（权威域名服务器）。

    6. SOA 记录（Start of Authority Record）：包含有关区域的权威信息，如主服务器、管理员邮箱、序列号等。

    7. PTR 记录（Pointer Record）：用于反向 DNS 解析，将 IP 地址映射到域名。

    8. TXT 记录（Text Record）：可用于提供任意文本信息，常用于验证域名所有权、设置 SPF 记录等。

    9. SRV 记录（Service Record）：用于指定特定服务的服务器位置和端口。

    10. CAA 记录（Certificate Authority Authorization，证书颁发机构授权）：是 DNS 中的一种新型记录类型，用于指定哪些证书颁发机构（CA）被授权为域名颁发 SSL/TLS 证书。

      • 通过设置 CAA 记录，域名所有者可以明确指定允许的 CA，防止未经授权的 CA 为其域名颁发证书，从而降低域名被恶意或错误颁发证书的风险。

    11. 泛记录：通过使用通配符 * 来匹配子域名的DNS记录。

      • 例如：*.example.com，指的是当有任何未知的 example.com 的子域名都会被解析到 *.example.com 这条记录。

    云DNS解析

    线路类型

    • 全网默认：如果没有设置其他线路，则返回默认解析结果。
    • 运营商线路：根据访问的用户所在的运营商网络调度到对应的线路。
    • 地域线路：根据访问的用户所处地理位置调度到对应的线路。

    TTL

    指记录在本地DNS服务器的缓存时间。也就是修改了记录后，需要等待TTL超时，才能够更新到新的DNS记录。

    举例： 配置中 www.example.com 指向 192.168.1.100，修改成 192.168.10.100 后：

    • 通过 ping 命令发现记录已经被修改过来
    • 但如果通过DNS工具进行解析，发现还是原来的记录，需要 TTL 过期后才可以解析到最新的记录

    日志

    主配置文件中通过 logging 字段定义了日志，默认的日志位置为 /var/named/data/named.run。

    DNS的客户端工具

    nslookup

    1. 查询域名对应的 IP 地址：直接输入 nslookup 域名，例如：nslookup www.example.com，它将返回该域名对应的 IP 地址。

    2. 指定 DNS 服务器进行查询：nslookup 域名 DNS服务器地址，例如：nslookup www.example.com 8.8.8.8，使用指定的 8.8.8.8 这个 DNS 服务器来查询。

    1. 交互式模式：输入 nslookup 进入交互式模式，然后可以输入域名进行查询。在交互式模式下，可以使用 set 命令设置一些参数，例如：

    2. set type=mx：查询 MX 记录

    3. set type=cname：查询 CNAME 记录

    dig（最强）

    1. 基本查询：要查询域名的 A 记录，可输入：dig example.com A。类似地，可指定其他记录类型，如 MX、CNAME 等。

    1. 指定 DNS 服务器：dig @8.8.8.8 example.com，使用 8.8.8.8 这台 DNS 服务器进行查询。

    1. 查看详细信息：添加 +trace 选项可以查看 DNS 解析的详细跟踪过程，例如：dig +trace example.com

    1. 批量查询：可以将多个域名放在一个文件中，然后使用 -f 选项进行批量查询。

    1. 输出格式控制：使用 +short 选项只输出简洁的结果。

    host

    1. 基本域名查询：输入 host example.com，它将返回 example.com 的 IP 地址。

    1. 指定查询类型：

    2. host -t MX example.com 用于查询 MX 记录

      - host -t CNAME example.com 用于查询 CNAME 记录

    3. 显示详细信息：使用 -v 选项获取更详细的输出。

    疑问：为什么我们在服务端什么都没有配置却可以解析出公网的域名呢？

    因为在 /etc/named.conf 配置文件里，默认开启了递归查询 recursion yes;。当我们发送了一个公网DNS查询后，DNS服务器就会向根域名服务器发送DNS查询。

    [root@server ~]# cat /etc/named.conf | grep 'recursion no;'
recursion no;
[root@localhost ~]# nslookup baidu.com
Server:         192.168.100.100
Address:        192.168.100.100#53
** server can't find baidu.com: REFUSED

    7. 配置正向区域文件

    [root@server ~]# vim /var/named/example.com.zone
$TTL 1D
@       IN SOA  ns.example.com admin.example.com (
                    0          ; serial
                    1D         ; refresh
                    1H         ; retry
                    1W         ; expire
                    3H )       ; minimum
        NS      ns.example.com.    # 声明DNS权威服务器是ns.example.com
        A       192.168.100.100    # 将当前区域example.com解析到192.168.100.100
ns      A       192.168.100.100    # 将权威服务器解析到192.168.100.100
www     A       192.168.100.100
qyt     A       192.168.100.100
shqytang CNAME  qyt.example.com.
mail    A       192.168.100.100
@       MX 5    mail.example.com
    • ns.example.com：权威域名服务器的名称
    • admin.example.com：管理员的电子邮件地址（将 @ 替换为 .，防止冲突）
