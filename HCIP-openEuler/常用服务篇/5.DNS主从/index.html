    DNS主从

    概述

    DNS 主备是 DNS 服务中的一种常见架构设置。主 DNS 服务器处于正常工作状态时，承担着绝大部分的 DNS 解析请求。它存储着完整且最新的 DNS 区域数据，并负责及时更新和维护这些数据。备用 DNS 服务器则时刻处于待命状态，它与主 DNS 服务器保持数据同步，以确保在主服务器出现问题时能够无缝接管服务。

    主备 DNS 服务器之间的数据同步可以通过多种方式实现，比如定期的区域文件传输、基于数据库的同步或者使用特定的同步工具和协议。

    在实际应用中，比如一个大型网站的 DNS 服务，如果主 DNS 服务器因遭受网络攻击、硬件故障或软件错误而无法正常工作，备用 DNS 服务器能够迅速响应，继续为用户提供准确的域名解析服务，从而最大程度减少对网站访问的影响。

    DNS主备本身并没有负载均衡的实现，所以客户端需要同时指定主和备。

    普通主备配置演示

    拓扑

    1. 搭建DNS主服务器

    1.1 修改主配置文件 /etc/named.conf

    [root@server ~]# vim /etc/named.conf
options {
    listen-on port 53 { any; };         # 监听在所有端口
    listen-on-v6 port 53 { ::1; };
    directory          "/var/named";
    dump-file          "/var/named/data/cache_dump.db";
    statistics-file    "/var/named/data/named_stats.txt";
    memstatistics-file "/var/named/data/named_mem_stats.txt";
    secroots-file      "/var/named/data/named.secroots";
    recursing-file     "/var/named/data/named.recursing";
    allow-query        { any; };        # 允许所有人访问
};

    1.2 修改区域配置文件 /etc/named.rfc1912.zones

    [root@server ~]# vim /etc/named.rfc1912.zones
zone "example.com" IN {
    type master;
    file "example.com.zone";
    allow-update { none; };              # 不允许客户端对区域记录进行更改
    allow-transfer { 192.168.100.200; }; # 允许该IP进行同步
    notify yes;                          # 启用通告变更，当主服务器区域文件发生变更后，通知从服务器进行比较同步
    also-notify { 192.168.100.200; };    # 指定需要发送notify的地址，当区域文件被改动，都会向这些地址发送notify消息
};

    1.3 复制并编辑区域文件

    [root@server ~]# cp -a /var/named/named.localhost /var/named/example.com.zone
[root@server ~]# vim /var/named/example.com.zone
$TTL 1D
@       IN SOA  ns.example.com admin.example.com (
                    1          ; serial
                    1D         ; refresh
                    1H         ; retry
                    1W         ; expire
                    3H )       ; minimum
        NS      ns.example.com.         # 声明DNS权威服务器是ns.example.com
@       A       192.168.100.100         # 将当前区域example.com解析到192.168.100.100
ns      A       192.168.100.100         # 将权威服务器解析到192.168.100.100
www     A       192.168.100.100
qyt     A       192.168.100.100
shqytang CNAME  qyt.example.com.
mail    A       192.168.100.100
@       MX 5    mail.example.com

[root@server ~]# systemctl restart named

    1.4 检查相关配置文件

    [root@server ~]# named-checkconf /etc/named.conf

    2. 搭建DNS从服务器

    2.1 修改主配置文件 /etc/named.conf

    [root@Slave ~]# vim /etc/named.conf
options {
    listen-on port 53 { any; };         # 监听在所有端口
    listen-on-v6 port 53 { ::1; };
    directory          "/var/named";
    dump-file          "/var/named/data/cache_dump.db";
    statistics-file    "/var/named/data/named_stats.txt";
    memstatistics-file "/var/named/data/named_mem_stats.txt";
    secroots-file      "/var/named/data/named.secroots";
    recursing-file     "/var/named/data/named.recursing";
    allow-query        { any; };        # 允许所有人访问
};

    2.2 修改区域配置文件 /etc/named.rfc1912.zones

    [root@Slave ~]# vim /etc/named.rfc1912.zones
zone "example.com" IN {
    type slave;
    file "slaves/example.com.zone";
    masters { 192.168.100.100; };
    masterfile-format text;
};
[root@Slave ~]# systemctl restart named

    2.3 检查相关配置文件

    [root@Slave ~]# named-checkconf /etc/named.conf

    DNS主从服务器的域维护

    DNS主从服务器的域维护是指通过DNS协议来在主域名服务器和从域名服务器之间维护同一个区域文件的操作。

    DNS支持两种域维护的方式：全量传输（AXFR） 和 增量传输（IXFR）。

    全量传输（AXFR）

    全量传输时，DNS从服务器会从DNS主服务器上请求区域文件，其间隔时间由SOA记录中的 refresh 标签所定义。请求区域文件的过程是DNS从服务器向DNS主服务器发送查询来实现的，如果DNS主服务器中SOA记录中的序列号(serial)大于DNS从服务器SOA记录的序列号，DNS从服务器就会向DNS主服务器发送全量传输请求。全量传输使用TCP的53端口进行传输。

    增量传输（IXFR）

    传递非常大的区域文件是非常耗资源的（时间、带宽等），尤其是只有区域中的一个记录改变的时候，没有必要传递整个区域文件，增量传输是允许DNS主服务器和DNS从服务器之间只传输那些改变的记录。

    通告 NOTIFY

    DNS从服务器会每隔SOA记录中设置的 refresh 时间值来向DNS主服务器发送请求，只有在主服务器的 serial 大于从服务器的 serial 时才进行传输，但是倘若 refresh 值设置得比较大，那么有可能在这段时间中就会积累大量的更新，此时DNS的时效性就会很差。

    此时 notify通告 就提供了这样的功能：DNS主服务器的zone文件发生改变后，它立即向从服务器发送一个NOTIFY消息，告诉从服务器"我的zone文件发生改变了"，接着从服务器马上对比两者的序列号，再采用上面介绍的全量传输或者增量传输的方法请求zone文件。

    BIND本身支持通告，通告的配置是在 named.conf 中的 zone 中的 option 中配置，配置指令是 notify、also-notify 和 notify-source。

    智能DNS

    智能 DNS 是一种先进的 DNS 服务技术，它能够根据不同的请求来源和条件，返回不同的 DNS 解析结果。

    智能 DNS 的主要特点和优势包括：

    1. 地域导向：根据用户的地理位置，将其请求解析到距离较近的数据中心或服务器，从而减少数据传输的延迟，提高访问速度和用户体验。
    2. 例如，来自中国的用户访问网站时，智能 DNS 会将其解析到位于中国境内的服务器 IP 地址。
    3. 线路优化：根据用户所使用的网络运营商（如电信、联通、移动等），将其引导至相应运营商的服务器，避免跨运营商访问带来的网络延迟和不稳定。
    4. 负载均衡：可以将流量分配到多个服务器上，以平衡服务器的负载，防止某一台服务器过载。
    5. 这里的负载均衡指的不是DNS服务器的负载均衡。
    6. 故障切换：当某一服务器出现故障时，智能 DNS 能够自动将请求指向其他正常运行的服务器。

    例如，一家拥有多个数据中心分布在全球不同地区的跨国企业，通过智能 DNS 技术，能够确保欧洲的用户访问欧洲的数据中心，亚洲的用户访问亚洲的数据中心，从而实现快速响应和优质的服务。

    实验：智能DNS配置

    通过配置智能DNS，实现客户端的地址是 192.168.100.51 时，解析 www.example.com，结果是 192.168.1.1。当客户端的地址是 192.168.100.52 时，解析 www.example.com，结果是 192.168.1.2。

    模拟公司内的内部网络和外部网络。

    1.1 配置DNS服务器的区域配置文件

    注意：当你配置了view后，所有的区域文件必须包含在view里！

    [root@server ~]# vim /etc/named.rfc1912.zones
view "1" {
    match-clients { 192.168.100.51/32; };
    zone "example.com" {
        type master;
        file "example1.com.zone";
    };
};

view "2" {
    match-clients { 192.168.100.52/32; };
    zone "example.com" {
        type master;
        file "example2.com.zone";
    };
};

    1.2 配置区域文件

    [root@server ~]# cat /var/named/example1.com.zone
$TTL 1D
@       IN SOA  ns.example.com rname.invalid. (
                    0          ; serial
                    1D         ; refresh
                    1H         ; retry
                    1W         ; expire
                    3H )       ; minimum
        NS      ns.example.com.
ns      A       192.168.100.100
www     A       192.168.1.1

[root@server ~]# cat /var/named/example2.com.zone
$TTL 1D
@       IN SOA  ns.example.com rname.invalid. (
                    0          ; serial
                    1D         ; refresh
                    1H         ; retry
                    1W         ; expire
                    3H )       ; minimum
        NS      ns.example.com.
ns      A       192.168.100.100
www     A       192.168.1.2
