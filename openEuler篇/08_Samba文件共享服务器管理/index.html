    08_Samba文件共享服务器管理

    1.基础概念

    1.1.为什么需要Samaba

    不同的操作系统使用不同的协议进行文件和打印共享。在Windows中使用SMB或CIFS实现文件共享，例如打开文件资源管理器，输入\\IP时，Windows就在使用SMB协议进行通信。而Linux使用的是NFS或其他的软件进行文件共享。

    在这种情况下，不同的操作系统想要互传文件，需要使用配套的服务端和客户端。怎么能够让Windows丝滑的通过\\IP直接访问Linux的共享文件呢？——Samba

    samba的核心功能：

    • 文件共享：允许Linux/Unix系统作为文件服务器，与Windows客户端共享文件。
    • 打印机共享：允许Linux/Unix系统共享打印机，供Windows客户端使用。
    • 身份验证：支持Windows用户的身份验证，包括本地用户和域用户。

    1.2.核心协议

    Samba或Windows传输文件和打印机使用的核心协议是SMB和CIFS。CIFS可以理解为是SMB协议的一个分支（方言），是微软在九十年代提出的，但在现在已经淘汰了。当今把所有新版和旧版都统称为SMB协议，CIFS特指那个旧版本。

    特性 CIFS（通常指 SMB1） 现代 SMB（SMB2, SMB2.1, SMB3.x）
    本质 一个特定草案，是 SMB 的一个“方言” 协议家族，是对 SMB 协议的持续发展和现代化
    设计年代 20 世纪 90 年代末 2006 年至今
    效率 低效，“聊天”过多。大量数据包用于协商和元数据。 高效。复合请求、更大的读写尺寸，减少网络往返。
    安全性 薄弱。依赖旧的、不安全的认证（如 NTLMv1）。 强大。支持 AES-128/256 加密、安全的身份验证（如 Kerberos）。
    可扩展性 差。难以添加新功能。 强。为未来扩展而设计。
    状态管理 无状态（某种程度上）。服务器不跟踪客户端连接。 有状态。服务器维护连接上下文，提高性能。
    常用端口 主要依赖 TCP 139（需要 NetBIOS 会话服务） 主要使用 TCP 445（纯 TCP/IP）
    1.2.1.SMB协议介绍

    SMB 是一种应用层网络协议，主要功能是提供对服务器上文件、目录、打印机、串行端口等共享资源的并发、受控的远程访问。

    • 核心价值：在网络上实现透明的文件访问，让远程文件感觉就像存储在本地一样。
    • 工作模式：客户端-服务器模型。
    • SMB 客户端：如 Windows Explorer、macOS Finder、Linux 上的 smbclient或挂载的 cifs文件系统。它发起请求。
    • SMB 服务器：如 Windows Server、Samba、NAS 设备。它响应请求并管理资源。
    1.2.2.SMB通信过程

    1. 协议协商：

    2. 客户端和服务端通信后，需要协商双方支持的最高版本的SMB协议。

    3. 客户端发送一个 NEGOTIATE请求，列出自己支持的所有 SMB 版本（如 SMB2.002, SMB3.0, SMB3.1.1）。服务器从中选择一个它支持的最高版本，并在响应中确认。

    4. 用户认证：

    5. 客户端向服务端发送SESSION_SETUP请求，其中包含身份验证信息，用于验证客户端身份。
    6. 树连接：
    7. 认证成功后，客户端发送 TREE_CONNECT请求，指定要访问的共享名（如 \\Server\Share）。服务器验证该用户是否有权访问此共享后，返回一个 树标识符
    8. 认证是进入公司大门（服务器），而树连接是进入某个特定的部门办公室（共享）。
    9. 文件访问：
    10. 客户端使用一系列命令对文件进行操作：
      • CREATE： 打开或创建文件/目录，获取一个文件句柄。
      • READ： 从文件句柄读取数据。
      • WRITE： 向文件句柄写入数据。
      • CLOSE： 关闭文件句柄。
      • GET_INFO/ SET_INFO： 查询或设置文件属性（元数据）。
    11. 断开连接：
    12. 通信结束时，客户端会依次发送 TREE_DISCONNECT（离开部门） 和 LOGOFF（离开公司） 请求。
    1.2.3.NetBIOS协议

    NetBIOS 是一个网络应用程序编程接口，而不是一个严格的网络协议。

    • 诞生年代： 1980 年代，由 IBM 和 Sytek 公司开发。
    • 原始目的： 为了让应用程序在局域网上相互通信。

    你可以把它理解成网络通信的 “寻址和会话管理”服务。它主要解决了三个基本问题：

    1. 网络上的设备叫什么名字？（名称服务）
    2. 如何把数据可靠地发送给某个会话？（会话服务）
    3. 如何快速地向所有人广播消息？（数据报服务）

    在现代的网络中DNS已经完全替代NetBIOS了，现代 Windows 系统（自 Windows 2000 起）支持 “直接托管”的 SMB，它直接使用 TCP 445 端口，完全绕开了 NetBIOS 层。

    • 客户端直接尝试连接服务器的 TCP 445 端口进行 SMB 通信。
    • 如果失败，才会作为备选方案回退到使用 TCP 139（NetBIOS over TCP/IP）。

    1.3.核心组件

    1. smbd（SMB 守护进程）：
    2. 职责：这是 Samba 的核心。负责管理共享资源（目录和打印机），处理来自客户端的连接、身份验证、文件访问和锁定。客户端实际的数据交换都通过它。
    3. 端口：通常运行在 TCP 139 和 445 端口。
    4. nmbd（NetBIOS 名称守护进程）：
    5. 职责：负责名称解析。在传统的 Windows 网络中，计算机不是通过 IP 地址被发现的，而是通过 NetBIOS 名称（就是你给电脑起的名字，如 MY-PC）。nmbd的作用就是将计算机名解析为 IP 地址，这样你才能在“网络邻居”里看到你的 Samba 服务器。
    6. 端口：通常运行在 UDP 137 和 138 端口。
    7. 注意：在现代纯 IP 网络（如仅使用 DNS）中，它的作用在减弱，但为了兼容性通常仍需开启。
    8. winbindd：
    9. 职责：这是一个高级功能的组件。当 Samba 服务器加入一个 Windows 域 或 Active Directory 时，winbindd负责与域控制器通信，解析域用户和组的信息。它让 Linux 系统能够“认识”域中的用户。
    10. samba-ad-dc：
    11. 职责：当 Samba 被配置为 Active Directory 域控制器 时，这个进程会运行，提供完整的域服务，类似于 Windows Server。

    简单来说：smbd管干活，nmbd管报名。

    1.4.服务套件

    1. samba软件包：
    2. 这是 Samba 服务器的本体。如果你想把这台Linux机器变成一台文件共享服务器，让Windows等机器来访问，就必须安装这个包。
    3. 包含内容：
      • 主要守护进程：smbd和 nmbd这两个最核心的后台进程的可执行文件。
      • 系统服务配置：用于 systemd或 init的启动脚本和配置文件，确保 Samba 服务能随系统开机自启。
      • 文档与日志工具：说明文档、日志轮替配置等。
    4. samba-common：
    5. 提供 Samba 运行时所必需的公共文件和工具，无论你的机器是做服务器还是做客户端，这个包都是必须的。它通常是 samba和 samba-client包的依赖项，会被自动安装。
    6. 包含内容：
      • 主配置文件：/etc/samba/smb.conf。这是 Samba 的灵魂，所有共享设置、安全策略都在这里定义。
      • 语法检验工具：testparm。这是一个极其重要的工具，在你修改完 smb.conf后，用它来检查配置文件是否有语法错误，避免因配置错误导致服务启动失败。
      • 其它 Samba 运行所需的公共库和基础文件。
    7. samba-client：
    8. 当你的Linux机器需要作为客户端，去访问网络中其他SMB/Samba共享资源时，就需要这个包。

    2.配置解析

    2.1.openEuler安装samba

    [root@qyt-gujun ~]# yum install samba -y

    2.2.配置文件解析

    smb.conf文件是一个基于节的配置文件。主要分为两部分：

    • [global]节：全局设置，对这个Samba服务器生效。
    • 共享定义节：每个节定义一个共享资源，如目录或打印机。
    # 这是一个注释
[global]
    # 全局参数在这里设置
    workgroup = MYGROUP
    server string = My Samba Server

[shared_folder_1]
    # 第一个共享的参数
    path = /srv/share1
    read only = no

[shared_folder_2]
    # 第二个共享的参数
    path = /srv/share2
    valid users = alice, bob
    2.2.1.全局配置介绍
    1. 网络与身份标识：
    参数 示例 说明
    workgroup WORKGROUP 定义服务器所属的工作组或域名。必须与你的 Windows 客户端的工作组一致。
    server string File Server %v 服务器的描述信息，会在网络邻居中看到。%v表示 Samba 版本号。
    netbios name MYSERVER 设置服务器的 NetBIOS 名称（不超过15字符）。如果不设，默认使用主机名。
    1. 安全与认证：
    参数 常用值 说明
    security user 最常用。Samba 使用自己的用户数据库（smbpasswd）进行认证。
    ads 服务器加入 Active Directory 域，使用域用户进行认证。
    domain 服务器加入 NT4 风格的域。
    passdb backend tdbsam 默认。使用 TDB 数据库文件（passdb.tdb）存储用户信息，适用于独立服务器。
    ldapsam 使用 LDAP 目录服务存储用户信息，用于大型网络。
    1. 日志与排错：
    参数 示例 说明
    log level 1 日志级别。0 基本无日志，1 是默认，2 以上为调试信息（排错时有用，但不要长期设置太高）。
    log file /var/log/samba/log.%m 日志文件路径。%m会自动替换为客户端 IP/名称，便于为每个客户端生成独立日志。
    max log size 1000 单个日志文件的最大大小（KB），超过后会轮替。
    1. 协议与性能：
    参数 示例 说明
    server min protocol SMB2_02 强烈建议设置。禁止不安全的 SMB1 协议，强制使用更高版本。
    server max protocol SMB3 设置服务器支持的最高 SMB 协议版本。
    socket options TCP_NODELAY 调整网络套接字选项以优化性能，对广域网或高速局域网有用。

    预配解析：

    [global]
        workgroup = SAMBA   # 服务器所属的工作组或域名
        security = user # 安全认证模式

        passdb backend = tdbsam # 用户与密码的存储方式

        printing = cups # 打印系统的集成方式
        printcap name = cups    # 指定打印系统的配置文件路径
        load printers = yes # 是否自动加载系统中的所有打印机并共享
        cups options = raw  # 表示直接发送原始打印数据到打印机，不进行额外的格式转换。

        include = /etc/samba/usershares.conf    # 加载其他配置文件
    2.2.2.共享常用参数
    [共享名称]
    comment = 共享描述
    path = 共享路径
    browseable = yes/no
    writable = yes/no
    valid users = 用户列表
    guest ok = yes/no
    create mask = 文件创建权限掩码
    directory mask = 目录创建权限掩码
    read only = yes/no
    public = yes/no
    available = yes/no

    基本设置：

    参数 必需？ 说明
    path 是 指定要共享的目录在 Linux 文件系统上的绝对路径。
    comment 否 共享的描述信息，帮助用户识别。

    访问控制：

    参数 说明 示例
    browseable 是否允许在网络邻居中“看到”这个共享名。不影响直接访问。 browseable = yes
    guest ok 是否允许匿名用户（不需要密码）访问。通常与 public同义。 guest ok = no
    read only 共享是否为只读。yes只读，no可读写。 read only = no
    writable 与 read only相反。yes可读写，no只读。 writable = yes
    valid users 明确指定允许访问此共享的用户列表（逗号分隔）。最安全的方式。 valid users = alice, bob, @marketing（@marketing表示 marketing 组）
    write list 拥有写权限的用户列表，即使 read only = yes。 write list = alice, @admins
    read list 拥有只读权限的用户列表，即使 read only = no。 read list = guest, @guests

    权限与文件系统集成：

    参数 说明 示例
    create mask 控制客户端新建文件的 Linux 权限掩码。 create mask = 0644（文件权限：rw-r--r--）
    directory mask 控制客户端新建目录的 Linux 权限掩码。 directory mask = 0755（目录权限：rwxr-xr-x）
    force user 所有通过共享进行的文件操作，都强制以该 Linux 用户身份执行。用于统一权限。 force user = share_user
    force group 类似 force user，但强制设置组身份。 force group = share_group
    2.2.3.特殊的共享

    [homes]

    当用户（如 alice）连接时，Samba 会自动将其家目录（如 /home/alice）共享为 [homes]。

    [homes]
    comment = Home Directories
    browseable = no # 不要在网络上显示 [homes] 这个共享名
    writable = yes
    valid users = %S # %S 代表当前登录的用户名

    用户 alice通过 \\server\alice访问自己的家目录，而不是 \\server\homes。

    [printers]

    这个节会自动共享Linux系统上已配置的打印机。

    [printers]
    comment = All Printers
    path = /var/spool/samba # 打印队列目录
    browseable = no
    guest ok = no
    printable = yes # 必须设为 yes，表示这是打印机共享

    2.3.samba的用户

    • 双重身份验证：
    • Samba 用户必须首先是一个 Linux 系统用户（存在于 /etc/passwd中）。
    • 然后通过 smbpasswd或 pdbedit工具将其添加到 Samba 的用户数据库（如 tdbsam或 ldapsam）。
    • 密码独立：
    • Samba 用户的密码可以与系统登录密码不同，由 Samba 独立管理。
    • 例如：用户 alice的 Linux 登录密码为 123456，但 Samba 密码可设为 samba_secure。

    匿名用户：

    匿名用户 指的是一个未经过身份验证的网络用户。当客户端访问Samba共享时，它没有提供、或者提供了一个无效/空的用户名和密码。

    在Samba的配置逻辑中，这类访问会被映射为一个特定的、权限极低的 Guest 账户。

    2.4.实验

    在openEuler上配置samba的两种共享：

    1. 安全共享（需用户名/密码访问，精细权限控制）。
    2. 匿名共享（无需密码，仅限读取）。
    2.4.1.安装samba
    [root@qyt-gujun ~]# yum install samba -y
    2.4.2.创建共享目录
    • 创建一个只有授权用户能访问的共享目录 /srv/secure_share，用户 user1和 user2可读写，user3只能读取。
    [root@qyt-gujun ~]# mkdir -p /srv/secure_share
[root@qyt-gujun ~]# chmod 775 /srv/secure_share/    # 组与用户可读写   
[root@qyt-gujun ~]# groupadd smbusers   # 创建组
[root@qyt-gujun ~]# chown :smbusers /srv/secure_share/  # 修改所属组

[root@qyt-gujun ~]# useradd -M -s /usr/sbin/nologin user1   # 创建用户，禁止登录
[root@qyt-gujun ~]# useradd -M -s /usr/sbin/nologin user2
[root@qyt-gujun ~]# useradd -M -s /usr/sbin/nologin user3
[root@qyt-gujun ~]# usermod -aG smbusers user1  # 将用户加入smbusers组
[root@qyt-gujun ~]# usermod -aG smbusers user2
[root@qyt-gujun ~]# usermod -aG smbusers user3
[root@qyt-gujun ~]# smbpasswd -a user1  # 设置smaba用户密码与系统密码独立
New SMB password:
Retype new SMB password:
Added user user1.
[root@qyt-gujun ~]# smbpasswd -a user2
New SMB password:
Retype new SMB password:
Added user user2.
[root@qyt-gujun ~]# smbpasswd -a user3
New SMB password:
Retype new SMB password:
Added user user3.
    2.4.3.配置共享目录
    [root@qyt-gujun ~]# vim /etc/samba/smb.conf
[SecureShare]
    comment = 安全共享（需密码访问）
    path = /srv/secure_share
    valid users = @smbusers      # 允许 smbusers 组的成员访问
    read list = user3           # user3 只读
    write list = user1, user2    # user1 和 user2 可读写
    browseable = yes            # 允许发现
    guest ok = no               # 禁止匿名访问
    create mask = 0664          # 新建文件权限
    directory mask = 0775       # 新建目录权限
    2.4.4.配置匿名访问
    [root@qyt-gujun ~]# mkdir -p /srv/public_read
[root@qyt-gujun ~]# chown nobody: /srv/public_read/
[root@qyt-gujun ~]# chmod 755 /srv/public_read

[root@qyt-gujun ~]# vim /etc/samba/smb.conf
[global]
        map to guest = baduser  # 当提供的用户名不存在或密码错误时，将其映射为匿名用户
        guest account = nobody  # 匿名用户在Linux系统上映射为nobody
[PublicRead]
    comment = 公共只读共享（匿名访问）
    path = /srv/public_read
    browseable = yes
    guest ok = yes               # 允许匿名访问
    read only = yes              # 只读
    guest only = yes             # 强制所有访问者为匿名用户
    force user = nobody          # 所有操作以 nobody 身份执行

    命令 功能 示例
    ls或 dir 列出当前目录文件 smb: \> ls
    cd 切换目录 smb: \> cd Documents
    get 下载文件 smb: \> get file.txt
    put 上传文件 smb: \> put local.txt
    mget 批量下载（支持通配符 *） smb: \> mget *.pdf
    mput 批量上传 smb: \> mput *.txt
    mkdir 创建目录 smb: \> mkdir NewFolder
    rm 删除文件 smb: \> rm old.txt
    rmdir 删除目录 smb: \> rmdir OldDir
    exit或 quit 退出 smb: \> exit
