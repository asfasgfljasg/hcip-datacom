    07_系统管理

    1.任务管理

    1.1.什么是任务管理？

    在系统运维的过程中，可能需要在某个预设的时间执行特定任务，比如定时发送邮件、备份并清空日志文件等任务。任务的内容可以看作是一系列命令或者一个脚本。

    任务管理可分为计划执行（特定时间运行一次）和定期执行（周期性执行多次）。

    1.2.at命令：一次性定时任务

    at是Linux系统中在指定时间执行一次性任务的工具。它适用于布置临时性任务，如：

    • 5分钟后关机
    • 明天早上8点发送邮件
    • 下周一运行一个脚本
    1.2.1.设置时间

    at允许你使用 相对时间（如 "5分钟后"）或 绝对时间（如 "2025-10-15 14:30"）来安排任务。

    相对计时：

    相对计时指的是从当前时间开始进行计算，对于安排不久后就要执行的命令较为方便，如：两个小时后、两分钟后、两天后、两周后。

    格式：now +X [minutes|hours|days|weeks]

    • now：指从当前时间开始计算。
    • X：代表时间的数量，几天、几小时、几周等。
    • minutes（分钟）
    • hours（小时）
    • days（天）
    • weeks（周）

    示例：

    at now+4 hours 
at now+240 minutes

    绝对计时：

    绝对计时适用于需要在固定时间点执行的任务（如 明天8:00或2025-12-25）

    格式：HH:MM [YYYY-MM-DD] 或 特殊时间关键词

    at HH:MM [AM|PM] [YYYY-MM-DD]   # 指定具体时间
at 时间关键词           # 如 midnight, noon, teatime

    at使用一套相当复杂的时间指定方法：

    • HH:MM（小时 分钟）指定时间，如果不加[YYYY-MM-DD]那代表在当天的时间执行，如果指定的时间已经过去，则任务会在第二天的同一时间执行。
    • 采用12小时计时制，即在时间后面加上AM或PM说明是上午还是下午。
      • at hh:mm[AM|PM]
    • 模糊时间关键词：
    • midnight- 深夜（00:00）
    • noon- 中午（12:00）
    • teatime- 饮茶时间（通常为16:00）

    总结：

    类型 语法 示例 说明
    绝对时间 HH:MM at 14:30 当天时间，过时则次日
    模糊时间 关键词 at teatime 使用预定义时间点
    12小时制 hh:mm[AM\|PM] at 4:30PM 需注明上午/下午
    具体日期 HH:MM 日期 at 09:00 Oct 20 2025 日期在时间后
    相对时间 now +X 单位 at now +1 hour 从当前时间延迟
    1.2.2.使用方式

    at有两种使用方式：命令行与交互式

    1. 交互式模式（默认）：进入 at提示符后输入命令，按 Ctrl+D结束。
    2. 命令行模式：直接通过 echo或 <<EOF传递命令，无需交互。

    基本语法：

    at [时间]

    交互式模式：

    1. 一分钟后执行echo命令：
    [root@qyt-gujun ~]# at now+1 minutes
warning: commands will be executed using /bin/sh
at Tue Oct 14 22:45:00 2025
at> echo "Hello" > ~/test.txt
at> <EOT>
job 1 at Tue Oct 14 22:45:00 2025

[root@qyt-gujun ~]# cat test.txt
Hello
    1. 14:30执行echo命令：
    [root@qyt-gujun ~]# at 14:30
warning: commands will be executed using /bin/sh
at Wed Oct 15 14:30:00 2025
at> echo "hELLO" > ~/test.txt
at> <EOT>
job 2 at Wed Oct 15 14:30:00 2025
    1. 上午10点30分执行echo命令：
    [root@qyt-gujun ~]# at 10:30AM
warning: commands will be executed using /bin/sh
at Wed Oct 15 10:30:00 2025
at> echo "111" > ~/test.txt
at> <EOT>
job 3 at Wed Oct 15 10:30:00 2025
    1. 模糊时间关键词
    # 深夜执行系统清理
at midnight <<EOF
rm -rf /tmp/*
echo "系统清理完成" >> /var/log/clean.log
EOF

# 中午执行每日报告
at noon <<EOF
/home/scripts/daily_report.sh
EOF

# 下午茶时间发送提醒
at teatime <<EOF
notify-send "Tea Time!" "记得休息一下喝杯茶"
EOF

    命令行模式：

    at命令的-f选项允许用户将一个包含多个命令的文件作为任务输入。

    at [时间] -f /path/to/file
    • [时间]：支持所有标准 at时间格式（绝对/相对时间）
    • -f：指定包含命令的文件
    • /path/to/file：包含要执行命令的文件路径

    示例：

    # 创建任务文件
[root@qyt-gujun ~]# cat at_job.sh
echo "Hello from at!" > ~/test.txt

# 安排5分钟后执行
[root@qyt-gujun ~]# at now+1 minutes -f ~/at_job.sh
warning: commands will be executed using /bin/sh
job 6 at Tue Oct 14 23:03:00 2025

[root@qyt-gujun ~]# cat test.txt
Hello from at!

    at可通过标准输入直接传递需要执行的命令。通过这种方式，不需要实现准备脚本文件，而是可以直接在命令行中输入你想要执行的命令或一系列命令。

    [root@qyt-gujun ~]# echo "echo 'test2' > test2.txt " | at now+1 minutes
warning: commands will be executed using /bin/sh
job 7 at Tue Oct 14 23:08:00 2025

[root@qyt-gujun ~]# cat test2.txt
test2

    查看任务：

    atq

    或

    at -l
    • 第一列：任务ID（如 3）
    • 第二列：执行时间
    • 最后一列：任务所属用户

    查看任务详情：

    at -c 任务ID

    at任务实际存储在 /var/spool/at/目录中：

    sudo ls -l /var/spool/at/
    • a0003→ 任务ID=3
    • c0006→ 任务ID=6

    1.3.cron命令：周期性任务

    cron是Linux系统中用于 周期性任务调度 的核心工具，适合需要 每天/每周/每月固定时间执行 的任务（如日志清理、数据备份等）。

    与 at（一次性任务）不同，cron专为 重复性任务 设计。

    1.3.1.基础概念

    核心组件

    组件 作用
    crond服务 后台守护进程，负责执行计划任务
    crontab命令 用户级任务管理工具（编辑/列出/删除任务）
    /etc/cron.\*/ 系统级任务目录（如 cron.daily/）
    • 用户任务：通过 crontab -e编辑，存储在 /var/spool/cron/用户名
    • 系统任务：存放在 /etc/crontab或 /etc/cron.d/目录
    特性 用户任务 系统任务
    所属对象 普通用户或 root 用户 系统管理员（通常仅 root 操作）
    管理命令 crontab -e 直接编辑文件或放置脚本
    存储位置 /var/spool/cron/用户名 /etc/crontab或 /etc/cron.d/
    执行身份 任务所属用户 需在文件中指定用户（如 root）
    典型用途 用户级自动化（如备份个人文件） 系统维护（如日志轮转、服务检查）

    cron启动之后，先检查是否有用户设置了crontab文件，如果没有就转入睡眠状态，释放系统资源。所以后台进程占用资源极少，之后每分钟被唤醒一次，查看当前是否有需要允许的命令。

    1.3.2.crontab基本使用

    用户任务：

    1. 编辑当前用户的任务：
    2. 文件格式：每行一个任务，遵循 时间 + 命令的格式
    crontab -e  # 打开编辑器（默认使用 vi/vim）
    1. 查看现有任务：
    crontab -l  # 列出当前用户的任务
    1. 删除所有任务
    crontab -r  # 慎用！会清空所有任务

    系统用户：

    1. 方法一：直接编辑/etc/crontab文件

    2. 方法二：使用/etc/cron.d目录

    # 1. 创建任务文件
sudo vim /etc/cron.d/my-custom-job

# 2. 设置正确权限
sudo chmod 644 /etc/cron.d/my-custom-job
    1.3.3.cron时间格式
    * * * * * command_to_run
│ │ │ │ │
│ │ │ │ └── 星期几 (0-7, 0和7=周日)
│ │ │ └──── 月份 (1-12)
│ │ └────── 日 (1-31)
│ └──────── 小时 (0-23)
└────────── 分钟 (0-59)
30 14 5 * *
* 5 * * *
0
    符号 说明 示例
    * 任意值 * * * * *→ 每分钟
    , 多个值 0,15,30 * * * *→ 每小时的0,15,30分
    - 范围 0 9-18 * * *→ 每天9点到18点整点
    */n 间隔 */10 * * * *→ 每10分钟
    1.3.4.示例
    1. 每天自动清理临时文件：
    2. 时间：每天凌晨3点
    3. 作用：删除7天前的临时文件
    [root@qyt-gujun ~]# vim /etc/crontab
0 3 * * * root find /tmp -type -f -mtime +7 -delete
    1. 每周日备份系统日志：
    [root@qyt-gujun ~]# crontab -e
0 2 * * 0 tar -czf /backup/logs_$(date +\%Y\%m\%d).tar.gz /var/log

    • 时间：每周日凌晨2点

    • 注意：%需转义为 \%

    • 提示：

    • no crontab for root - using an empty one crontab: installing new crontab

      • no crontab for root：

      表示 root 用户当前 没有配置过任何定时任务（首次使用 crontab -e时会看到此提示）。

      • using an empty one：

      cron 系统为你打开一个 空文件 供编辑。

      • installing new crontab：

      当你保存退出后，系统会将编辑的内容安装为 root 的新定时任务。

    • 每月一号检查磁盘空间：

    • 时间：每月1日午夜
    [root@qyt-gujun ~]# crontab -e
0 0 1 * * df -h > /var/log/disk_usage.log
    1. 查看当前用户定时任务：
    [root@qyt-gujun ~]# crontab -l
0 2 * * 0 tar -czf /backup/logs_$(date +\%Y\%m\%d).tar.gz /var/log

    1. 删除任务：crontab -e进入删除对应行

    2. 清空所有任务：crontab -r

    2.网络管理

    2.1.Linux地址配置方式

    • ifconfig：传统方式，已经淘汰，配置临时生效。
    • ip命令：替代ifconfig、route等传统工具，配置临时生效，立即生效。
    • 配置文件：通过修改网卡配置文件实现，配置永久生效，需要重启网络服务或系统才能生效。
    • NetworkManager：
    • nmcli：命令行形式，配置永久生效但需要重启网卡或系统，相对复杂。
    • nmtui：图形化形式，配置永久生效但需要重启网卡或系统，相对简单。
    2.1.1.ip命令

    ip命令是Linux系统中功能强大的网络配置工具，属于 iproute2软件包，它替代了传统的 ifconfig、route等命令。

    ip [OPTIONS] OBJECT COMMAND

    常用OBJECT：

    • link：网络设备
    • addr：IP地址
    • route：路由表
    • neigh：ARP/NDISC缓存

    示例：

    1. 查看所有网络接口状态：
    [root@qyt-gujun ~]# ip link show
1: lo: <LOOPBACK,UP,LOWER_UP> mtu 65536 qdisc noqueue state UNKNOWN mode DEFAULT group default qlen 1000
    link/loopback 00:00:00:00:00:00 brd 00:00:00:00:00:00
2: ens33: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc fq_codel state UP mode DEFAULT group default qlen 1000
    link/ether 00:0c:29:71:a0:54 brd ff:ff:ff:ff:ff:ff
3: ens34: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc fq_codel state UP mode DEFAULT group default qlen 1000
    link/ether 00:0c:29:71:a0:5e brd ff:ff:ff:ff:ff:ff
    1. 启用/禁用网络接口：
    ip link set ens33 up
ip link set ens33 down
    1. 查看ip地址：
    ip addr / ip addr show  # 查看全部接口的IP地址
ip add show ens33   # 查看指定接口IP地址
    1. 添加IP地址：
    [root@qyt-gujun ~]# ip addr add 192.168.80.200/24 dev ens33 # 在ens33网卡上添加IP地址
    1. 删除IP地址：
    [root@qyt-gujun ~]# ip addr del 192.168.80.101/24 dev ens33
    1. 修改IP地址：修改的方式是添加与删除组合
    2.1.2.配置文件方式

    Linux中一切皆文件，即使你使用ip、nmtui、nmcli等工具对IP地址进行配置，最终也是以配置文件的形式在系统上呈现的。所以，最彻底的方式就是直接修改或创建配置文件。

    配置文件的位置：

    /etc/sysconfig/network-scripts/ifcfg-eth0

    配置文件解释：

    参数 说明
    TYPE 配置文件接口类型
    BOOTPROTO 系统启动地址协议
    ONBOOT 系统启动时是否激活
    IPADDR IP 地址
    NETMASK 子网掩码
    GATEWAY 网关地址
    BROADCAST 广播地址
    HWADDR/MACADDR MAC 地址，只需设置其中一个，同时设置时不能相互冲突
    PEERDNS 是否指定 DNS，如果使用 DHCP 协议，默认为 yes
    DNS{1, 2} DNS 地址
    USERCTL 用户权限控制
    NAME 网络连接名称
    DEVICE 物理接口名称 
    TYPE=Ethernet   # 接口类型为以太网
PROXY_METHOD=none   # 不使用任何代理
BROWSER_ONLY=no # 不限制仅浏览器使用此连接
BOOTPROTO=none  # 设置为none表示静态配置IP，DHCP表示自动获取IP
DEFROUTE=yes    # 将此连接作为默认路由
IPV4_FAILURE_FATAL=no   # IPv4失败处理，如果IPv4配置失败，不视为致命错误
IPV6INIT=yes    # 启用IPv6
IPV6_AUTOCONF=yes   # IPv6自动获取地址
IPV6_DEFROUTE=yes   # 将此连接作为IPv6的默认路由
IPV6_FAILURE_FATAL=no   # 如果ipv6配置失败，不视为致命错误
NAME=ens33  # 网络连接的逻辑名称
UUID=f16588a6-6d01-4cfe-a9ce-9bd9f8377ca4   # 网卡唯一标识符，系统自动生成
DEVICE=ens33    # 物理网络接口名称
ONBOOT=yes  # 系统启动时自动激活此连接
IPADDR=192.168.80.101   # IPv4地址
PREFIX=24   # 掩码
GATEWAY=192.168.80.2 # 网关
DNS1=192.168.80.2   # dns服务器地址

    link/ether 00:0c:29:71:a0:5e brd ff:ff:ff:ff:ff:ff

    [root@qyt-gujun ~]# cp -a /etc/sysconfig/network-scripts/ifcfg-ens34 /etc/sysconfig/network-scripts/ifcfg-ens37
    1. 生成UUID：
    [root@qyt-gujun ~]# uuidgen

    3.进程管理

    3.1.什么是进程？

    进程（Process）是计算机中已运行程序的实体，是程序的一个具体实现。

    • 程序的实体：程序是静态的，是硬盘上的一个文件（usr/bin/firefox）。而进程是这个程序被加载到内存后，开始执行时的动态实体。可以理解为程序是菜谱，进程是炒菜的过程。

    • 资源分配的单元：操作系统为了管理进程，需要给它分配各种资源，比如内存、CPU、打开的文件等。进程就是系统进行资源分配和调度的基本单位。每个进程都有自己独立的空间，互不干扰。

    • 拥有唯一标识的实例：系统为了区分和管理成千上万的进程，会给每个进程分配一个唯一的身份证号——PID。

    比喻：

    • 程序：就像一份菜谱（番茄炒蛋.pdf）。
    • 进程：就是厨师根据这份菜谱，动用厨房的灶台（CPU）、锅碗瓢盆（内存）、食材（数据）来实际烹饪一道番茄炒蛋（进程）的过程。餐厅可以同时有多个厨师用同一份菜谱炒菜，这就是多个进程对应一个程序。
    • PID：就是给这个烹饪过程分配的一个订单号，方便管理。

    3.2.进程的生命周期

    系统当中所有的进程都是以父子的形式存在的，第一个系统进程是systemd，其他所有进程都是其后代。

    父子进程机制的意义，从根本上说，是为了实现任务管理和资源管理的分离与协作。

    举个例子：你使用的Shell（如Bash）就是一个父进程。当你输入 ls命令时，Shell并不自己执行 ls的功能，而是创建一个子进程去执行。这样，无论 ls是成功、失败还是崩溃，Shell本身都能保持稳定运行，并准备好接收你的下一条命令。子进程只需要专注于完成任务，将失败或成功的结果告知父进程即可。

    任何进程都可以通过复制自己地址空间的方式（fork）创建子进程，子进程中记录着父进程的ID(PPID)。

    1. fork()：创建子进程
    2. 父进程调用fork()创建一个新的进程（子进程）。
    3. 子进程是父进程的一个副本，它获得父进程的代码、数据、堆栈等内存空间的拷贝。
    4. 子进程拥有一个新的、唯一的进程ID。

    5. 子进程的父进程ID 被设置为调用 fork()的那个进程的PID。

    6. exec()：执行新程序

    7. 子进程被创建后，通常会立即调用exec()，exec()会用磁盘上的一个新程序（例如 /bin/ls）的代码和数据，完全替换掉当前子进程的地址空间。
    8. 子进程的PID保持不变。
    9. 子进程不再执行父进程的代码，而是开始执行新程序的代码。
    10. exit()：终止进程
    11. 子进程完成其任务后，调用 exit()系统调用。进程终止，释放其占用的所有资源（内存、文件等），但保留其进程描述符。
    12. 此时，进程进入 “僵尸状态” 。它已经死亡，不再运行，但在内核的进程表中仍保留一个条目（记录其退出状态等信息），等待其父进程读取。
    13. wait()：回收资源
    14. 父进程调用 wait()或 waitpid()系统调用。如果其子进程已经终止（处于僵尸状态），wait()会立即返回，并读取该子进程的退出状态。然后，系统会彻底释放该子进程的所有残留资源（包括进程描述符），僵尸进程被完全清除。如果子进程仍在运行，父进程默认会在 wait()处阻塞（睡眠），直到子进程终止。

    3.3.进程的状态

    一个进程在CPU上并不是一直运行着的，它可能正在运行，可能在等待，也可能已经结束了但是没有被处理。进程状态就是用来描述进程当前正在做什么的标签。

    按照正常流程-->睡眠等待-->特殊状态的顺序来讲解。

    1. 运行状态：
    2. 就绪态：表示进程已经准备好了所有运行条件，等待操作系统调度器把CPU分配给他。当前状态下进程正在排队。通常是睡眠或暂停的进程被唤醒或继续后，就会进入就绪态排队。
    3. 用户运行态：进程正在CPU上执行其自身的程序代码。处理用户程序的。
    4. 内核态运行：进程正在CPU上执行操作系统内核的代码。处理系统程序的。
    5. 睡眠/等待状态：
    6. 可中断睡眠状态：进程在等待一个可能时间较长的事件，比如等待用户输入、等待网络数据等。这种睡眠可以被信号唤醒。
    7. 不可中断睡眠状态：进程也在等待事件（如磁盘读写），但这个状态下的进程绝不会被任何信号打断。这是为了保护内核的某些关键流程不被打断。
    8. 特殊状态：
    9. 暂停状态：进程的执行被人为或主动的暂停了，但它仍然是可活动的可以被恢复的。例如ctrl+z。
    10. 僵停状态：进程已经终止运行，释放了所有资源，但它在内核的进程表项（PCB）还没有被清除。它等待其父进程来读取它的退出状态。

    3.4.进程的优先级

    可以把CPU想象成一个大厨，进程就是大厨的烹饪订单。如果所有订单都一视同仁，那么一个慢炖3小时的订单，就会把所有其他订单堵住，导致系统响应缓慢。

    进程的优先级就是为了解决这个问题的，它决定了CPU资源分配的先后顺序。优先级高的进程会被优先处理，优先级低的进程需要排队。

    [root@openEuler ~]# ps -l
F S   UID     PID    PPID  C PRI  NI ADDR SZ WCHAN  TTY          TIME CMD
0 S     0  686110  686109  0  80   0 -  3383 do_wai pts/0    00:00:00 bash
0 S     0  686217  686110  0  80   0 -  3386 do_wai pts/0    00:00:00 bash
0 R     0  688767  686217  0  80   0 -  3399 -      pts/0    00:00:00 ps

    当执行ps -l命令后，会看到两个与优先级相关的列：PRI和NI：

    • PRI(Priority)优先级：

    • 这是进程实际的、由内核调度器使用的优先级。

    • 核心规则：PRI值越小，进程的优先级越高，越先被CPU执行

    • 优先级（PRI）范围 描述
      0—99 实时进程
      100—139 非实时进程

    • NI(Nice Value)谦让度：

    • 这不是优先级本身，而是用来影响和修正 PRI的一个数值。用户可以修改的就是这个 NI值。
    • 取值范围：通常是 -20 到 19。
    • 默认值：普通用户创建的进程，NI默认为 0。
    • 作用规则：NI值越小，进程就变得越“不自谦”，就会导致最终的 PRI值变小，从而提升优先级。反之，NI值越大，进程越“谦让”，优先级越低。

    最终优先级 PRI(new)= 初始优先级 PRI(old)+ NI值

    管理进程优先级：

    • nice：以指定优先级启动进程，在启动一个命令时就直接设置它的NI值。

    • 命令格式：nice -n <NI值> <命令>

    • nice -n -15 ls # 以高优先级（谦让度低）启动一个任务

    • 注意：普通用户只能设置 0 到 19 的 NI值（即只能降低或保持优先级）。设置负值（提高优先级）需要 root权限。

    • renice：调整已运行进程的优先级

    • 命令格式：renice -n <新的NI值> -p <进程PID>

    • ``` [root@qyt-gujun ~]# ps aux | grep sshd root 951 0.0 0.2 13936 7324 ? Ss 23:30 0:00 sshd: /usr/sbin/sshd -D [listener] 0 of 10-100 startups root 1602 0.0 0.2 15400 9164 ? Ss 23:33 0:00 sshd: root [priv] root 1604 0.0 0.1 15736 5276 ? S 23:33 0:00 sshd: root@pts/0 root 1605 0.0 0.2 15400 9144 ? Ss 23:33 0:00 sshd: root [priv] root 1673 0.0 0.1 15400 4752 ? S 23:33 0:00 sshd: root@notty root 1737 0.0 0.0 22112 2296 pts/0 S+ 23:33 0:00 grep --color=auto sshd

      [root@qyt-gujun ~]# renice -n 10 -p 951 951 (process ID) 旧优先级为 0，新优先级为 10

      [root@qyt-gujun ~]# ps aux | grep sshd root 951 0.0 0.2 13936 7324 ? SNs 23:30 0:00 sshd: /usr/sbin/sshd -D [listener] 0 of 10-100 startups root 1602 0.0 0.2 15400 9164 ? Ss 23:33 0:00 sshd: root [priv] root 1604 0.0 0.1 15736 5276 ? S 23:33 0:00 sshd: root@pts/0 root 1605 0.0 0.2 15400 9144 ? Ss 23:33 0:00 sshd: root [priv] root 1673 0.0 0.1 15400 4752 ? S 23:33 0:00 sshd: root@notty root 1740 0.0 0.0 22112 2384 pts/0 S+ 23:33 0:00 grep --color=auto sshd

      [root@qyt-gujun ~]# ps -eo pid,ppid,ni,pri,comm | grep sshd 951 1 10 9 sshd 1602 951 0 19 sshd 1604 1602 0 19 sshd 1605 951 0 19 sshd 1673 1605 0 19 sshd ```

    • 在 ps命令的 STAT输出中，N 这个标志的含义正是 “该进程的谦让度（nice值）被设置为正数（即低优先级）”。

    3.5.前台进程与后台进程

    • 前台进程：
    • 占用终端：执行期间，Shell 无法接受新命令。
    • 直接输出：所有输出（stdout/stderr）都会直接显示在终端。
    • 可被中断：
      • Ctrl + C→ 终止进程（SIGINT）
      • Ctrl + Z→ 暂停进程（SIGTSTP）
    • 后台进程：
    • 不占用终端：进程在后台运行，用户可以继续输入命令。
    • 输出仍可能显示：默认情况下，后台进程的输出仍会显示在当前终端（可能干扰用户输入）。
    • 不会被 Ctrl+C终止：必须手动用 kill终止。

    控制前台与后台进程：

    • &：将&放在命令的最后，可以把这个命令放到后台执行
    • Ctrl + z：当前台正在执行一个命令时，按键Ctrl + z，将其放到后台并暂停
    • Ctrl + c：中断当前正在执行的命令
    • jobs：查看当前有多少正在后台运行的命令
    • fg：将后台中的命令调至前台继续运行
    • bg：将后台任务唤醒，并在后台运行

    3.6.查看进程

    3.6.1.PS命令

    用于静态查看当前系统的进程状态。适合快速查看某个时间点的进程信息。

    参数 作用 示例 适用场景

    ps -e 显示所有进程 ps -e 查看系统全部进程（简洁版）
    ps -f 显示完整格式（含 PPID） ps -f 查看进程父子关系
    ps -ef 显示所有进程的完整信息 ps -ef 最常用的进程查看方式（含 PPID）
    ps aux 显示所有进程的详细信息（BSD 风格） ps aux 查看进程的 CPU、内存占用
    ps -l 显示当前终端进程的详细信息（含 PRI/NI） ps -l 查看进程优先级
    ps -eo pid,ppid,ni,pri,comm 自定义输出列（PID、PPID、NI、PRI、命令名） ps -eo pid,ppid,ni,pri,comm 查看进程优先级和父子关系

    3.6.2.top命令

    top命令可以实时查看系统进程状态，类似于Windows的任务管理器。它可以动态显示 CPU、内存、进程负载 等信息，并支持交互式操作（如排序、终止进程）。

    3.7.信号

    在Linux中，信号（Signals） 是进程间通信的一种方式，用于通知进程发生了某种事件（如终止、暂停、继续等）。

    常见信号：

    信号编号 信号名 默认行为 用途
    1 SIGHUP 终止 挂起，通常用于让进程重新读取配置文件（如 nginx -s reload）
    2 SIGINT 终止 中断（等同于 Ctrl+C），请求进程终止
    3 SIGQUIT 终止+核心转储 结束运行（等同于 Ctrl+），请求进程终止并生成核心转储文件 j
    9 SIGKILL 强制终止 立即杀死进程，进程无法捕获或忽略此信号
    15 SIGTERM 终止 优雅终止（默认信号），进程可以清理后退出
    18 SIGCONT 继续 恢复被暂停的进程
    19 SIGSTOP 暂停 暂停进程（等同于 Ctrl+Z），进程无法捕获或忽略

    kill命令用于向进程发送信号：

    kill [-信号] PID
    • PID：要发送信号的进程 ID（可通过 ps或 top查看）。

    • -信号：可以是 信号编号（如 -9）或信号名（如 -SIGKILL）。

    • 默认行为

    kill 1234  # 向 PID=1234 的进程发送 SIGTERM（15），请求优雅退出
    1. 强制终止进程：
    kill -9 1234  # 强制杀死 PID=1234 的进程（无法被捕获或忽略）
    1. 暂停进程：
    kill -19 1234  # 暂停 PID=1234 的进程

    killall按照进程名发送信号：

    killall -9 nginx  # 杀死所有名为 "nginx" 的进程
