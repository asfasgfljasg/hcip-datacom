    05_软件包管理

    1.管理软件包

    1.1.软件包

    在Linux上安装一款软件，本质上是让一个程序在我们的系统上运行，他需要如下内容：

    要素 说明 举例
    1. 程序文件本身 可执行的二进制文件 /usr/bin/firefox
    2. 依赖库 程序运行需要的外部代码库 libc.so.6, libgtk-3.so.0
    3. 配置文件 程序的设置信息 /etc/nginx/nginx.conf
    4. 资源文件 图标、文档、帮助文件等 /usr/share/icons/hicolor/...
    5. 系统集成 菜单快捷方式、文件关联等 /usr/share/applications/firefox.desktop
    1.1.2.安装方式

    不同的安装方式，就是获取和布置上述要素的不同方法。在Linux上可以整体分为二进制安装和源码安装两种方式。

    源码安装和二进制安装的区别可以理解为，菜谱和成品菜的区别。

    源码安装：

    • 源码是程序员用编程语言（如 C, C++, Java, Python, Go）编写的原始源代码（通常是.tar.gz或.tar.xz等压缩格式）
    • 使用场景：
    • 软件仓库里没有你需要的软件或特定版本。
    • 你需要针对自己的硬件进行编译优化以获得最佳性能。
    • 你想修改源代码。
    • 安装流程：
    • ./configure：检查你的系统环境，配置编译选项。
    • make：开始编译源代码，生成二进制文件。
    • sudo make install：将编译好的文件安装到系统中。

    二进制安装：

    • 二进制包一般是由Linux发行版官方仓库、第三方仓库提供。
    • 获取到匹配Linux发行版的二进制包后，使用配套的软件包管理器进行安装即可。

    1.2.RPM

    RPM（RedHat Package Manager），由Red Hat提出的包管理系统，用于安装、查询、验证、更新和卸载软件包。在openEuler中需要本地获取软件的rpm包，通过RPM包管理器进行安装。默认情况下RPM包的安装、删除、更新只有root用户可以操作，查询则是所有用户都可以。

    RPM软件包命名格式：

    • name-version-release.arch.rpm
    • name：软件包名称
    • version：带有主、次和修订次数的软件包版本
    • arch：硬件平台
    • src.rpm：源代码包
    • vsftpd-3.0.5-2.oe2403.x86_64.rpm
    • vsftpd：软件包的名称
    • 3.0.5-2：前半部分代表版本号，2代表修订次数
    • oe2403：表示软件包的发行商版本
    • x86_64：表示软件包的硬件平台，适合的cpu架构。
    • 特殊名称：
    • devel：表示这个RPM包是软件的开发包
    • noarch：表示这个软件包可以在任何硬件平台上安装
    1.2.1.RPM的核心组件

    RPM的工作依赖以下关键部分：

    组件 作用
    RPM 包文件（.rpm） 包含编译好的二进制文件、依赖信息、安装脚本等。
    RPM 数据库 位于 /var/lib/rpm/，记录所有已安装包的元数据（文件列表、版本、依赖等）。
    rpm 命令工具 用户通过 rpm命令与数据库和包文件交互。
    1.2.2.RPM包的文件结构

    1. 文件清单

    2. 二进制可执行文件（如 /usr/bin/nginx）

    3. 配置文件（如 /etc/nginx/nginx.conf）

    4. 库文件（如 /usr/lib64/libnginx.so）

    5. 文档和手册（如 /usr/share/doc/nginx/README）

    6. 元数据（Metadata）

    7. 软件名称、版本、发布号（如 nginx-1.20.1-1.el8）

    8. 依赖关系（如 Requires: openssl >= 1.1.1）

    9. 签名信息（GPG 签名验证包的来源可信性）

    10. 脚本钩子（Scriptlets）：在安装/卸载前后自动执行的脚本：

    11. %pre：安装前执行（如创建用户）。

    12. %post：安装后执行（如启动服务）。

    13. %preun：卸载前执行（如停止服务）。

    14. %postun：卸载后执行（如清理残留文件）。

    1.2.3.RPM的工作流程

    安装流程：

    1. 检查依赖：rpm -ivh package.rpm
    2. RPM 读取包的 Requires字段，检查系统是否满足依赖（若未满足，需手动或通过 dnf安装）。
    3. 解压包内容：
    4. 将二进制文件、配置文件等解压到临时目录。
    5. 执行 %pre脚本：
    6. 运行安装前的自定义命令（如创建用户）。
    7. 部署文件到系统：
    8. 将文件复制到目标路径（如 /usr/bin、/etc）。
    9. 更新 RPM 数据库：
    10. 在 /var/lib/rpm/中记录包的元数据（文件列表、版本等）。
    11. 执行 %post脚本：
    12. 运行安装后的命令（如启动服务或更新系统配置）。

    查询流程：

    1. 读取 RPM 数据库：rpm -q
    2. 从 /var/lib/rpm/中检索已安装包的元数据。
    3. 返回结果：
    4. 例如 rpm -qi nginx显示包的详细信息（版本、安装时间等）。

    卸载流程： rpm -e package-name

    1. 执行 %preun脚本：
    2. 运行卸载前的命令（如停止服务）。
    3. 删除文件：
    4. 根据数据库记录，清理包安装的所有文件。
    5. 更新 RPM 数据库：
    6. 删除该包的元数据记录。
    7. 执行 %postun脚本：
    8. 运行卸载后的清理命令（如删除临时文件）。
    1.2.4.RPM的依赖管理

    依赖是指软件在Linux上运行所必须的外部组件，就像空气、水和食物对我们的意义。常见的依赖类型如下：

    1. 库依赖：提供基础功能，如加密、图形渲染。
    2. libssl.so.1.1（OpenSSL 库，用于 HTTPS 加密）
    3. libpng16.so（处理 PNG 图像）
    4. 工具依赖：运行时需要调用其他程序。
    5. python3（Python 解释器）
    6. bash（Shell 脚本解释器）
    7. 服务依赖：依赖后台服务才能工作。
    8. MySQL 客户端依赖 mysqld服务
    9. Docker 依赖 containerd服务

    依赖的声明方式：

    在RPM包元数据中的Requires字段，声明了该RPM在安装前，系统里必须预先存在的软件或者库。

    Requires: libssl >= 1.1.1
Requires: python3

    所以在安装RPM包时，系统会根据RPM报的依赖字段检查系统是否已经存在依赖的内容，如果存在则可以安装。如果不存在则提示用户，用户需要手动将依赖安装完毕。

    但是，在实际使用的过程中，安装A软件可能需要B依赖，安装B可能需要C依赖，这样就导致整个安装过程非常繁琐，这也是直接使用RPM安装的最大缺点。

    1.2.5.RPM的获取方式
    1. 在openEuler社区中下载RPM包：
    2. 例如：wget https://mirrors.aliyun.com/openeuler/openEuler-20.03-LTS-SP3/everything/x86_64/Packages/vsftpd-3.0.3-32.oe1.x86_64.rpm
    3. 通过第三方RPM包网站进行下载：
    4. https://rpmfind.net/
    5. 通过本地光盘镜像（安装介质）安装RPM包
    6. 需要把镜像挂载到Linux的具体目录
    1.2.6.RPM的验证机制

    对于RPM包我们需要有对应的验证机制，假设这个RPM包是通过第三方获取到的，有可能这个RPM包内部就是一个恶意脚本（rm -rf /），一旦我们使用RPM对其安装，脚本也会运行造成危害。

    RPM的验证机制是确保软件包完整性和安全性的核心功能，主要用于：

    1. 检测文件篡改（如配置文件被修改）
    2. 验证软件来源可信度（GPG签名）
    3. 排查软件安装异常（如文件丢失或权限错误）

    GPG数字签名

    对公钥和对RPM下发的软件中心是没有验证机制的

    GPG是RPM包验证的核心机制，用于确保软件包的真实性（来源可信）和完整性（未被篡改）。它的工作原理基于非对称加密和数字签名技术。公钥加密，私钥解密

    1. 开发者生成自己的GPG密钥对（验证身份）
    2. 私钥（~/.gnupg/secring.gpg）：严格保密，用于签名包。
    3. 公钥（~/.gnupg/pubring.gpg）：公开分发，供用户验证签名。
    4. 开发者将公钥导出为文件，并分发给用户或软件仓库

    5. 公钥位置：/etc/pki/rpm-gpg/RPM-GPG-KEY-openEuler

    6. 开发者在打包时使用私钥生成签名，签名会被写入RPM包的头部元数据中

    7. 使用哈希函数计算文件摘要，确保数据一致性
    8. 使用私钥加密哈希值，生成签名
    9. 生成的签名包含加密后的哈希值和时间戳，防止篡改和重放攻击
    10. 用户从可信来源获取公钥并导入RPM数据库：
    11. rpm --import /etc/pki/rpm-gpg/RPM-GPG-KEY-openEuler
    12. 用户验证签名：
    13. 使用公钥解密签名，获取原始的哈希值
    14. 计算下载文件的哈希值，并于解密出的哈希值对比
      • 一致代表文件未篡改
      • 不一致代表文件可能被修改或伪造
    1.2.7.RPM命令介绍

    安装RPM包：

    rpm -ivh [包名.rpm]      # 标准安装（i: install, v: 详细信息, h: 进度条）
    • --nodeps：忽略依赖检查（可能导致软件无法运行）
    • --force：强制覆盖已安装的包
    • --test：仅测试安装，不实际执行

    安装示例：

    1. 下载vsftpd安装包

    升级RPM包：

    rpm -Uvh [包名.rpm]      # 升级包（若未安装则自动安装）
    • -U会保留旧版配置文件（如 /etc/nginx/nginx.conf.rpmsave）。

    卸载RPM包：

    rpm -e [包名]            # 卸载包（只需包名，无需版本号）
    • --nodeps：忽略依赖检查
    • --test：模拟卸载

    2.YUM与DNF

    2.1.YUM

    你可以把YUM理解成一个高级版的RPM包管理器，它的核心作用是解决RPM包之间的依赖关系，并提供一个便捷的软件安装、更新、删除的自动化管理方式。

    2.1.1.工作原理
    1. 仓库是远端还是本地（定义了repo仓库文件）
    2. 本地：需要自己配置对应的文件
    3. 远端：需要定义远端仓库的仓库文件，需要保证该仓库可以正常连接
    4. yum命令

    1. 仓库（Repository）：
    2. YUM 不直接管理单个的 .rpm文件，而是从一个或多个软件仓库获取信息。
    3. 仓库是集中存放大量 RPM 包及其元数据（如依赖关系、版本信息）的服务器。
      • 元数据信息保存在repodata目录中，在安装软件前，会先查找repodata这个目录，确定依赖关系。
    4. 系统的仓库文件配置在 /etc/yum.repos.d/目录下的 .repo文件中。
    5. 元数据缓存：
    6. 当您执行 yum update或 yum makecache时，YUM 会从配置的仓库下载元数据（如所有可用包的列表、依赖关系等）并缓存在本地（/var/cache/yum/）。
    7. 这使得后续的搜索、安装等操作非常快速，因为不需要每次都去远程服务器查询。
    8. 依赖关系解析：
    9. 当您要安装软件包 A 时，YUM 会从本地缓存中查询软件包 A 依赖哪些包（比如 B 和 C），并且 B 和 C 可能又依赖其他包。
    10. YUM 会自动计算出所有需要安装的包，并生成一个事务，询问用户是否确认执行。
    11. 事务性操作：
    12. YUM 的操作是事务性的。这意味着它会先检查整个操作（包括所有依赖项的安装和冲突）是否可能成功。如果任何一步出错，整个操作都会回滚，系统将保持原状，这保证了系统的稳定性。
    2.1.2.软件仓库

    使用的仓库是通过Linux系统上的仓库配置文件定义：

    • /etc/yum.repos.d/，仓库配置文件格式为*.repo

    2.1.3.yum命令介绍

    软件包安装与删除：

    命令 说明
    yum install <package_name> 安装一个软件包及其所有依赖。
    yum remove <package_name> 删除一个软件包及其依赖它的包（如果不再被需要）。
    yum reinstall <package_name> 重新安装一个已存在的包。
    yum update 更新所有已安装的包到最新版本。
    yum update <package_name> 更新指定的软件包。

    查询与搜索：

    命令 说明
    yum search <keyword> 搜索软件包名称和描述中包含关键字的包。
    yum list 列出所有可用、已安装或可更新的包。
    yum list installed 列出所有已安装的包。
    yum list available 列出所有可安装但尚未安装的包。
    yum list updates 列出所有可更新的包。
    yum info <package_name> 显示一个软件包的详细信息（版本、大小、描述等）。
    yum provides <file_name> 查找哪个软件包提供了指定的文件或命令。

    系统仓库与管理：

    命令 说明
    yum check-update 检查可用的更新，但不实际执行更新。
    yum clean all 清理缓存中的元数据和软件包，释放磁盘空间。
    yum makecache 重建元数据缓存，确保本地信息是最新的。
    yum repolist all 列出所有已配置的仓库（启用和禁用的）。
    yum history 查看 YUM 操作历史，可以用于撤销操作。
    2.1.4.示例
    1. 搜索 nginx 包：
    yum search nginx
    1. 查看 nginx 包的详细信息：
    yum info nginx
    1. 安装 nginx（YUM 会自动解决依赖关系）：
    yum install nginx

    • 执行后，YUM 会列出所有将要安装的包（包括 nginx 及其依赖），并询问 Is this ok [y/d/N]:。输入 y并按回车确认。

    • 查看已安装的 nginx：

    yum list installed | grep nginx
    1. 如果需要删除 nginx：
    yum remove nginx

    2.2.DNF

    DNF（Dandified YUM）是 YUM 的下一代版本，在 RHEL 8+、CentOS 8+、Fedora 22+、openEuler 等系统中取代了YUM。

    DNF 的优势：

    • 兼容性：YUM只能使用python进行调用，而DNF可以使用任何语言开发插件并调用
    • 性能：DNF的内存占用更小，解析RPM包索引的速度更快
    • 轻量：DNF的代码量更少，只有不到5千行

    在openEuler中，yum和dnf这两个命令都指向dnf -3这个可执行程序，所以无论使用yum还是dnf命令，实际上都是调用dnf。

    [root@gugujun ~]# ls -l /usr/bin/yum
lrwxrwxrwx. 1 root root 5 Dec 27  2023 /usr/bin/yum -> dnf-3
[root@gugujun ~]# ls -l /usr/bin/dnf
lrwxrwxrwx. 1 root root 5 Dec 27  2023 /usr/bin/dnf -> dnf-3
    2.2.1.DNF本地源配置
    [root@gugujun ~]# mkdir /mnt/cdrom  # 创建被挂载的目录

[root@gugujun ~]# mount /dev/cdrom /mnt/cdrom   # 将本地镜像挂载
mount: /mnt/cdrom: WARNING: source write-protected, mounted read-only.

[root@gugujun ~]# cd /etc/yum.repos.d/  # 进入yum的配置目录

[root@gugujun yum.repos.d]# mv openEuler.repo openEuler.repo.bak    # 备份默认仓库文件

[root@gugujun ~]# vim /etc/dnf/dnf.conf
  [main]
  gpgcheck=1
  installonly_limit=3
  clean_requirements_on_remove=True
  best=True
  skip_if_unavailable=False
  [openEuler]   # 仓库的名字
  name=openEuler Packages   # 仓库的描述

  enable=1  # 仓库是否启用，为1表示开启，为0表示关闭，则在安装软件时系统不会在这个仓库下查找软件
  gpgcheck=1    # 是否校验软件的完整性，如果开启需要写公钥的位置
  gpgkey=/mnt/cdrom/RPM-GPG-KEY-openEuler   # RPM公钥的路径
