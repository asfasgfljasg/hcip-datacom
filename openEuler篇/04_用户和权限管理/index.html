    四、用户和权限管理

    1.管理用户和组

    1.1.用户的基础概念

    Linux操作系统是多用户、多任务的操作系统，它允许多个用户同时登录使用系统资源。每个用户都拥有唯一的用户名和密码。

    用户的作用：

    • 身份认证：识别使用系统的人或进程。
    • 权限控制：决定用户的权限范围，从而保障系统安全和个人隐私。

    用户的分类：

    • 普通用户：为实际使用系统的个人创建的账户。权限有限，只能管理自己的文件和目录，以及被授权访问的资源。
    • 超级用户（root）：拥有系统最高权限，可以执行任何操作，没有限制。
    • 虚拟用户：不可以登录到操作系统（默认分配的shell为/sbin/nologin），没有自己的家目录。为了运行系统服务或应用程序而创建的。

    UID：

    User ID使用户唯一的标识符，不同范围的UID代表不同类别的用户。Linux系统是通过UID区分用户的，而不是用户名。

    • 超级用户：UID为0。
    • 普通用户：UID范围为1000-60000。
    • 虚拟用户：UID范围为1-999。

    在Linux中可通过id命令查看用户的UID：

    id [option] [username]
参数：
  -g或--group 　 显示用户所属群组的ID。
  -G或--groups   显示用户所属附加群组的ID。
  -n或--name 　  显示用户，所属群组或附加群组的名称。
  -r或--real 　  显示实际ID。
  -u或--user 　  显示用户ID。
  -help 　       显示帮助。
  -version 　    显示版本信息。

    若直接输入id命令，则是显示当前用户和对应组的ID：

    [root@qyt-gujun ~]# id
用户id=0(root) 组id=0(root) 组=0(root)

    若在id命令后加上指定username，可现实指定用户和对应组的ID：

    [root@qyt-gujun ~]# id openeuler
用户id=1000(openeuler) 组id=1000(openeuler) 组=1000(openeuler),10(wheel)

    只显示用户名，不显示ID：

    [root@qyt-gujun ~]# id -un
root

    只显示用户ID，不显示用户名：

    [root@qyt-gujun ~]# id -u
0

    只显示主组ID：

    [root@qyt-gujun ~]# id -g
0

    只显示主组名：

    [root@qyt-gujun ~]# id -gn
root
    1.1.1.添加用户
    useradd [选项] 用户名
其中各选项含义如下：
  -c comment 指定一段注释性描述。
  -d 目录 指定用户主目录，如果此目录不存在，则同时使用-m选项，可以创建主目录。
  -g 用户组 指定用户所属的用户组。
  -G 用户组，用户组 指定用户所属的附加组。
  -s Shell文件 指定用户的登录Shell。 /bin/bash -s /sbin/nologin
  -u UID 指定用户的用户号，如果同时有-o选项，则可以重复使用其他用户的标识号。
  用户名 指定新账号的登录名。

    创建普通用户：

    useradd zhangsan

    创建用户并指定家目录：

    useradd -d /opt/zhangsan zhangsan

    创建用户并指定shell为/sbin/nologin：

    useradd wangwu -s /sbin/nologin

    创建用户并指定UID和主组：

    useradd -u 1001 -g developers username

    创建用户并添加多个附加组：

    useradd -G wheel,admins,developers username

    创建用户并设置备注信息：

    useradd -c "John Doe" username
    1.1.2.修改用户属性
    sudo usermod [选项] 用户名
    选项 说明
    -l或 --login 修改用户名（不会更改家目录）
    -d或 --home 修改用户的家目录（不会自动移动文件，需配合 -m）
    -m或 --move-home 将旧家目录内容移动到新目录（需与 -d一起使用）
    -s或 --shell 修改用户的默认 Shell（如 /bin/bash）
    -g或 --gid 修改用户的主组（GID 或组名）
    -G或 --groups 修改用户的附加组（多个组用逗号分隔）
    -a或 --append 添加附加组（不覆盖原有组，需与 -G一起使用）
    -u或 --uid 修改用户的 UID
    -L或 --lock 锁定用户（禁止登录）
    -U或 --unlock 解锁用户
    -e或 --expiredate 设置账户过期时间（格式：YYYY-MM-DD）
    -c或 --comment 修改用户备注（如全名）

    修改用户名：仅修改用户名，不会自动更改家目录名称。

    usermod -l new_username old_username

    修改用户家目录：

    usermod -d /new/home/dir username
    • -d指定新目录

    修改用户的shell：

    usermod -s /bin/bash username  # 改为 bash
usermod -s /sbin/nologin username  # 禁止登录

    修改用的主组：

    usermod -g new_primary_group username

    添加用户附加组：

    usermod -aG group1,group2 username
    • -aG表示 追加 附加组（不会覆盖原有组）
    • 如果只使用 -G不加 -a，会覆盖原有的附加组

    修改用户的UID：

    usermod -u 1005 username

    注意：修改 UID 后，需手动更新文件所有权

    sudo find / -user old_uid -exec chown -h new_uid {} \;

    锁定/解锁用户：

    usermod -L username  # 锁定（在 /etc/shadow 密码前加 !）
usermod -U username  # 解锁

    设置账号过期时间：

    usermod -e 2024-12-31 username
    1.1.3.创建或修改用户密码
    passwd [选项] [用户名]
    • 直接输入passwd即可修改当前账户的密码，passwd username可修改其他用户的密码，但普通用户只能修改自己的密码。
    选项 说明
    -l或 --lock 锁定用户（禁止登录）
    -u或 --unlock 解锁用户
    -d或 --delete 删除用户密码（允许无密码登录）
    -e或 --expire 强制用户下次登录时修改密码
    -S或 --status 查看密码状态（是否设置、是否锁定等）
    -n 天数 设置密码最短有效期（多少天内不能改密码）
    -x 天数 设置密码最长有效期（多少天后必须改密码）
    -w 天数 密码到期前多少天提醒用户
    -i 天数 密码过期后多少天禁用账户

    锁定用户：

    passwd -l username
    • 锁定后，用户无法登录（即使密码正确）。
    • 在 /etc/shadow中，密码前会加 !。

    解锁用户：

    passwd -u username

    删除用户密码：

    passwd -d username
    • 删除密码后，用户可以直接登录（不推荐，有安全风险）。
    • 在 /etc/shadow中，密码字段变为空。

    强制用户下次登陆时修改密码：

    passwd -e username

    查看密码状态：

    passwd -S username
[root@qyt-gujun ~]# passwd -S openeuler
openeuler PS 2025-09-26 0 99999 7 -1 (密码已设置，使用 SHA512 算法。)
用户名 密码状态 最后修改日期 最短有效期 最长有效期 警告期 宽限期
    字段 含义 示例值 说明
    用户名 用户账户名 openeuler 当前查询的用户
    密码状态 密码是否设置或锁定 P P=已设置密码，NP=无密码，LK=锁定
    最后修改日期 密码最后一次修改时间 2025-09-26 格式为 YYYY-MM-DD
    最短有效期 密码修改后多少天内不能再次修改 0 0表示无限制
    最长有效期 密码多少天后必须修改 99999 99999表示几乎永不过期
    警告期 密码到期前多少天提醒用户 7 到期前 7 天会收到警告
    宽限期 密码过期后多少天禁用账户 -1 -1表示永不禁用

    可用chage命令代替：

    [root@qyt-gujun ~]# chage -l openeuler
最近一次密码修改时间                                    ：9月 26, 2025
密码过期时间                                    ：从不
密码失效时间                                    ：从不
帐户过期时间                                            ：从不
两次改变密码之间相距的最小天数          ：0
两次改变密码之间相距的最大天数          ：99999
在密码过期之前警告的天数        ：7

    设置密码过期时间：

    passwd -x 90 username  # 密码 90 天后过期
passwd -w 7 username   # 过期前 7 天提醒
passwd -i 5 username   # 过期后 5 天禁用账户

    设置密码最短修改间隔：

    passwd -n 7 username  # 7 天内不能改密码
    1.1.6.删除用户
    userdel [选项] 用户名
    选项 说明
    -r 删除用户的同时删除家目录和邮件池
    -f 强制删除（即使用户已登录）
    -Z 同时删除用户的 SELinux 用户映射（仅适用于 SELinux 系统）

    删除用户但保留家目录：

    userdel username
    • 仅删除 /etc/passwd、/etc/shadow、/etc/group中的用户信息。
    • 家目录（如 /home/username）和邮件池（/var/mail/username）会保留。

    删除用户并删除家目录：

    userdel -r username
    • 删除用户的同时删除家目录（/home/username）和邮件池。
    • 适用于彻底清理用户数据。

    强制删除用户：

    userdel -f username
    • 强制删除用户，即使该用户当前有进程在运行。
    • 慎用，可能导致正在运行的程序崩溃。

    1.2.用户组的基础概念

    用户组是Linux中用户的集合，用于简化权限管理。通过将用户分组，可以批量设置文件/目录的访问权限。

    每个用户都有一个用户组，系统可以对用户组中的所有用户集中管理。默认情况下，创建用户的同时创建一个与该用户同名的用户组，并把该用户添加到同名组中。同一个组内的所有用户都可以共享该组拥有权限的文件和目录。

    用户组的分类：

    • 主组：
    • Linux上的任何用户都必须拥有一个主组。默认情况下，创建用户时若没有指定则自动创建与用户名相同的组，作为该用户的主组。
    • 用户的主组不能直接被删除、用户不能直接被移出主组，但可以更换主组。
    • 用户被删除时，若主组内没有其他用户，则系统会自动删除该主组。
    • 多个用户的主组是可以相同的。
    • 附加组：
    • 用户可以所属零或多个附加组，附加组可以直接被删除，无论组中是否有用户。

    • 用户被删除时，它的附加组不会收到任何影响。

    • 系统组：

    • 与系统用户的概念相同，是系统用户的组。

    GID：

    GID是用户组的ID，作为唯一标识符来标识系统中的用户组。

    • 在创建用户时，默认情况下会创建与用户名相同的用户组，且GID与UID也相同。
    1.2.1.创建用户组
    sudo groupadd [选项] 组名
    选项 说明
    -g GID 指定组的 GID（组ID）
    -r 创建系统组（GID 范围：1~999）
    -f 强制创建（如果组已存在，忽略错误）
    -o 允许重复使用 GID（需配合 -g）
    -p 密码 设置组密码（不安全，不推荐）

    创建普通组：

    groupadd developers  # 创建名为 developers 的组

    创建组并指定GID：

    groupadd -g 1005 testers  # 创建组并指定 GID 为 1005

    创建系统组：

    groupadd -r system_group  # 创建系统组（GID < 1000）

    查看用户组：

    [root@qyt-gujun ~]# getent group system_group
system_group:x:984: # 组名:密码占位符:GID:组成员
    1.2.2.修改用户组属性
    groupmod [选项] 组名
    选项 说明
    -n 新组名 修改组名（不会影响组成员）
    -g 新GID 修改组的 GID（需确保新GID未被占用）
    -o 允许重复使用 GID（需配合 -g）

    修改组名：

    groupmod -n new_group old_group

    修改组的ID：

    groupmod -g 新GID 组名
    1.2.3.管理用户组和成员
    gpasswd [选项] 组名
    选项 说明
    -a 用户名 将用户添加到组（作为附加组）
    -d 用户名 将用户移除出组
    -r 删除组的密码（允许无密码访问）
    -A 用户名 设置组的管理员（可管理组成员）
    -M 用户名列表 批量设置组成员（覆盖原有成员）
    -R 限制普通用户使用 newgrp切换组

    添加用户到组：

    gpasswd -a alice developers
    • 将用户 alice添加到 developers组（作为附加组）
    • 对比 usermod：gpasswd -a是追加，不会覆盖原有附加组

    从组中移除用户：

    gpasswd -d bob developers

    设置管理员：

    gpasswd -A alice developers
    • 用户 alice成为 developers组的管理员，可以自行添加/移除其他成员

    批量设置组成员：

    gpasswd -M alice,bob,charlie developers
    • 将 developers组的成员设置为 alice、bob、charlie（覆盖原有成员）
    1.2.4.删除用户组
    groupdel [选项] 组名
    选项 说明
    -f 强制删除（即使组是某些用户的主组）
    -h 显示帮助信息

    删除普通组：

    groupdel developers
    • 删除名为 developers的组
    • 前提：组不能是任何用户的主组（Primary Group）

    强制删除组：

    groupdel -f developers
    • 即使组是某些用户的主组，也强制删除
    • 后果：相关用户的主组GID会变成无效值，可能导致权限问题

    1.3.用户与用户组相关文件

    在Linux中一切皆文件，即用户与用户组的相关信息也会被记录到文件中。

    • /etc/passwd：用户账户信息。
    • /etc/shadow：用户密码及安全信息。
    • /etc/group：用户组信息。
    • .etc.gshadow：用户组密码及管理信息。
    1.3.1./etc/passwd

    在Linux中/etc/passwd记录了系统中每个用户的基础属性。在该文件中每一个用户都占用一行记录，且利用冒号分隔成7个字段。

    用户名:密码占位符(x):UID:GID:用户描述:家目录:登录Shell

    以root用户为例：

    root:x:0:0:root:/root:/bin/bash
    1. 用户名：用户登录名（如 alice）
    2. 密码占位符：x表示密码存储在 /etc/shadow
    3. UID：用户ID（0=root，1-999=系统用户，≥1000=普通用户）
    4. GID：主组ID
    5. 用户描述：备注信息（如全名）
    6. 家目录：用户的主目录路径
    7. 登录Shell：用户登录时使用的 Shell（如 /bin/bash）

    小实验：

    创建一个新用户并删除该用户在/etc/passwd中的密码占位符，随后登录该账户不需要密码：

    [root@qyt-gujun ~]# useradd gujun
[root@qyt-gujun ~]# vim /etc/passwd

    1.3.2./etc/shadow

    在Linux系统中，/etc/shadow是真正存放用户密码的文件，每一个用户占用一行，且用冒号分隔。普通用户无权访问该文件。

    用户名:加密密码:最后修改天数:最小修改间隔:密码有效期:警告期:宽限期:过期时间:保留字段

    以root用户为例：

    root:$y$j9T$nsqDN13T78xtye1eI3jhGff4$7sCxCEZbazgGjNcdEoNhUlgxUOCycVnv.eGC.Eakrg2::0:99999:7:::
    1. 加密密码：
    2. 格式：$加密算法$salt$哈希值（如 $6$=SHA-512）
    3. !或 *表示账户被锁定
    4. 空表示无密码（不安全）
    5. 最后修改天数：从 1970-1-1 到上次修改密码的天数
    6. 最小修改间隔：多少天后才能再次修改密码（0=无限制）
    7. 密码有效期：多少天后必须修改密码（99999=永不过期）
    8. 警告期：密码到期前多少天提醒用户
    9. 宽限期：密码过期后多少天禁用账户
    10. 过期时间：账户失效的绝对日期（从 1970-1-1 的天数）

    小实验：

    限制用户的具体操作：限制gujun用户只能查看某个文件：

    2. 密码占位符：x表示组密码在 /etc/gshadow

    2.文件与目录权限

    2.1.基础概念

    Linux将文件的权限分为三个类别：

    • 文件拥有者（owner）：
    • 在Linux中，创建一个文件时，该文件的拥有者便是创建该文件的用户。该文件的拥有者可以修改文件的拥有者及用户组。root用户可以修改任何文件的拥有者及用户组。
    • 文件所属组（group）：
    • 当在Linux上有多个用户共同开发一个项目时，便可灵活使用Group特性，这个文件或目录关联的用户组都会获得该文件的Group权限。
    • 其他人（others）：
    • 不属于文件拥有者和文件所属组的用户就是其他人，对于文件或目录来说，其他人就是访客。

    在Linux中最常用的方式是通过ls -l命令查看文件或目录的权限。每一组权限类别都由三种权限组成：rwx。

    • r (读取) - 数值为 4
    • w (写入) - 数值为 2
    • x (执行) - 数值为 1
    -rwxr-xr-- 
↑  ↑  ↑  ↑
│  │  │  └── 其他用户权限：读、不可写、不可执行
│  │  └───── 组权限：读、执行、不可写
│  └──────── 所有者权限：读、写、执行
└─────────── 文件类型（- 普通文件，d 目录，l 链接等）

    但是，目录与文件的rwx的含义并不相同：

    • 文件：

    • r：可读取文件中的内容

    • w：可以编辑、新增、修改文件的内容，但不可以删除该文件（删除该文件的权限在于时候拥有该文件所属目录的w权限）

    • x：该文件具有可以被系统执行的权限，在Linux中是不是一个执行文件（脚本）这是由x权限觉得的，而不是扩展名

    • 文件的x权限决定了你这个文件是不是脚本

    • 但是这个脚本能不能顺利出结果：1.x权限 2.后缀名 3.内容

    • 目录：

    • r(read)：显示目录列表，可以用ls命令查看
    • w(write)：允许在目录中新建、删除、改名、移动文件或子目录，总而言之就是改变目录下文件的结构
    • x：切换目录，进入该目录，对应cd命令

    2.2.命令介绍

    2.2.1.更改文件所有者和所属组
    chown [选项] 新所有者[:新组] 文件...
    • 更改文件或目录的所有者
    • 更改文件或目录的所属组（需要管理员权限）
    选项 说明
    -R 递归处理，更改目录及其内容的所有权
    -v 显示详细的处理信息
    -c 类似 -v，但只在有变更时才显示
    --reference=参考文件 使用参考文件的所有者和组

    更改文件所有者：

    chown user1 file.txt

    同时更改所有者和组：

    chown user1:group1 file.txt

    只更改组：

    chown :group1 file.txt

    递归更改目录下所有文件：

    chown -R user1:group1 directory/

    使用参考文件的权限：

    chown --reference=template.txt file.txt
    2.2.2.更改文件权限
    chmod [选项] 模式 文件...

    符号模式：

    [ugoa][+-=][rwxXst]
    • 用户类别：u(所有者)、g(组)、o(其他)、a(所有)
    • 操作符：+(添加)、-(移除)、=(设置)
    • 权限：r(读)、w(写)、x(执行)、X(特殊执行)、s(setuid/setgid)、t(粘滞位)

    数字模式：

    [0-7][0-7][0-7]
    • 每位数字代表：所有者|组|其他用户
    • 每位数值：4(r)+2(w)+1(x)

    常用选项：

    选项 说明
    -R 递归处理目录及其内容
    -v 显示详细变更信息
    -c 类似 -v，但只在有变更时显示
    --reference=参考文件 使用参考文件的权限

    使用示例：

    # 符号模式示例
chmod u+x script.sh        # 给所有者添加执行权限

chmod +t /tmp/             # 设置粘滞位

# 数字模式示例

chmod 644 config.txt       # rw-r--r--
chmod 600 private.key      # 仅所有者可读写

# 递归设置目录权限
chmod -R 750 directory/

# 使用参考文件权限
chmod --reference=template.txt file.txt

    2.3.umask

    umask（用户文件创建掩码）是一个权限掩码，用于确定新创建文件和目录的默认权限。它通过屏蔽不需要的权限位来工作。

    umask 是一个4位八进制数（虽然通常显示为3位），其结构如下：

    0 [特殊权限] [所有者权限] [组权限] [其他用户权限]
    • 第一位：特殊权限位（setuid, setgid, sticky bit）
    • 后三位：对应三类用户的权限掩码
    2.3.1.工作原理

    umask的计算方式是最大权限减去umask。

    • 文件默认权限：666 - umask
    • 常规文件默认不需要可执行x权限，所以最大权限为666。
    • 目录默认权限：777 - umask
    2.3.2.查看umask
    umask       # 显示当前umask（符号格式）
umask -S    # 以符号形式显示（如 u=rwx,g=rx,o=rx）
umask       # 通常显示数字格式（如0022）
    umask值 文件权限 目录权限 说明
    0022 644 (rw-r--r--) 755 (rwxr-xr-x) 默认值，组和其他用户无写权限
    0002 664 (rw-rw-r--) 775 (rwxrwxr-x) 组有写权限，其他用户无写权限
    0000 666 (rw-rw-rw-) 777 (rwxrwxrwx) 完全开放（不安全）
    0027 640 (rw-r-----) 750 (rwxr-x---) 其他用户无任何权限
    2.3.3.设置umask

    临时设置（仅当前会话有效）

    [openeuler@qyt-gujun ~]$ umask 0027
[openeuler@qyt-gujun ~]$ touch 1.txt
[openeuler@qyt-gujun ~]$ ll
总用量 0
-rw-r----- 1 openeuler openeuler 0  9月 27 22:56 1.txt

    永久设置

    [openeuler@qyt-gujun ~]$ vim .bashrc
umask 0027

    umask 不影响现有文件，只影响新创建的文件和目录

    2.4.特殊权限

    为了更方便、有效及安全的控制文件或其他资源服务，引入了一组特殊权限，被称为第四组权限。这组特殊权限又被进一步分为suid、sgid和sticky三种权限。Linux系统基本权限位有9位，但还有额外3位权限位，共12位权限位。

    2.4.1.suid

    该特殊权限用于针对命令和二进制程序的，当普通用户执行某个命令时，可以拥有这个命令对应用户的权限。即让普通用户可以以root用户的身份执行命令。此权限为仅针对二进制可执行文件有效。

    举例：

    当普通用户需要修改自己的密码，但是/etc/passwd文件普通用户是没有权限的。

    [root@qyt-gujun ~]# ll /etc/passwd
-rw-r--r--. 1 root root 1613  9月 18 20:45 /etc/passwd

    这就会导致普通用户无法修改自己的密码：

    [root@qyt-gujun ~]# ll /usr/bin/passwd
-rwsr-xr-x. 1 root root 30952 12月 28  2023 /usr/bin/passwd

    setuid让普通用户临时获得root权限，所以当普通用户输入passwd命令时，以root权限运行passwd命令，并以root用户权限将新密码写入到/etc/passwd。

    • 最小权限原则：不需要给普通用户root权限
    • 受控特权访问：只在执行特定程序时获得提升的权限
    • 审计追踪：可以监控特定程序的特权使用情况

    命令：

    # 符号方式
chmod u+s /path/to/file
chmod 4755 /path/to/file    # 数字方式（4表示setuid）

# 移除setuid
chmod u-s /path/to/file
chmod 755 /path/to/file

    现象：

    [root@qyt-gujun ~]# ll
总用量 4
-rw-------. 1 root      root      1131  9月 18 20:46 anaconda-ks.cfg
-rws------  1 openeuler openeuler    0  9月 27 22:44 test1.txt
-rwSr--r--  1 openeuler openeuler    0  9月 27 22:44 test.txt

    小写s代表该文件所有者有执行权限，且文件设置了setuid权限。当执行此文件时，会以文件所有者的身份运行。

    大写S代表该文件所有者没有可执行权限，且文件设置了setuid权限。该设置是无效的因为文件不可执行。

    2.4.2.sgid

    SGID（Set Group ID）是Linux系统中的一种特殊权限，它有两种不同的作用场景：

    针对可执行文件：

    当 SGID 权限被设置在一个可执行程序上时，无论哪个用户执行这个程序，该程序在运行期间都会临时获得其所属用户组的权限，而不是执行者本身的所属组权限。

    • 工作原理： 正常情况下，用户执行一个程序，该进程的“有效组ID”就是用户自己的组ID。但如果程序文件设置了 SGID，进程的“有效组ID”就会变成程序文件所属的组ID。
    • 目的： 这通常用于让多个用户能够共享某种资源。例如，一个数据库程序 (/usr/bin/db_program) 属于 dba组并设置了 SGID。那么，无论是 userA还是 userB执行它，这个程序都能以 dba组的权限去访问数据库文件，即使用户本身并不在 dba组中。

    针对目录：

    这是 SGID 一个更常用、更重要的功能。当对一个目录设置 SGID 权限时，任何用户在该目录下创建的新文件或子目录，其所属组都会自动继承该目录的所属组，而不是创建者本人的主要组。

    • 工作原理： 假设有一个共享目录 /opt/shared_project，其所属组是 project_team，并且设置了 SGID。当 userA（主要组为 userA）在此目录中创建一个新文件时，这个新文件的所属组会自动变成 project_team，而不是 userA。
    • 目的： 这是实现团队协作的利器。它能确保一个项目目录下的所有文件都属于同一个组，这样所有团队成员（只要是 project_team组的成员）都能正常读写这些文件，避免了因文件所属组不同而导致的权限问题。

    设置方式：

    # 为目录设置 SGID
chmod g+s /path/to/directory

# 为文件设置 SGID
chmod g+s /path/to/file

chmod 2775 /path/to/directory

    示例：

    [root@qyt-gujun ~]# groupadd test
[root@qyt-gujun ~]# usermod -aG test openeuler
[root@qyt-gujun ~]# mkdir /opt/test
[root@qyt-gujun ~]# chown :test /opt/test
[root@qyt-gujun ~]# chmod 2775 /opt/test
[root@qyt-gujun ~]# ll /opt/test -d
drwxrwsr-x 2 root test 4096  9月 27 23:27 /opt/test

[openeuler@qyt-gujun ~]$ cd /opt/test
[openeuler@qyt-gujun test]$ touch 1.txt
[openeuler@qyt-gujun test]$ ll
总用量 0
-rw-r----- 1 openeuler test 0  9月 27 23:28 1.txt
    2.4.3.sbit

    SBIT 的全称是 Sticky Bit，中文常翻译为“粘滞位”或“限制删除位”。SBIT 的唯一且最重要的作用是：当一个目录设置了 SBIT 后，该目录中的文件，只有以下三种用户能够删除（或重命名）它

    1. 文件的所有者
    2. 目录的所有者
    3. 超级用户 (root)

    如果没有设置 SBIT，只要用户对目录有写权限（w），他就可以删除该目录下的任何文件，即使那个文件不属于他。

    设置方式：

    chmod o+t /path/to/shared_directory

chmod 1777 /path/to/shared_directory

    示例：

    [root@qyt-gujun ~]# useradd gujun
[root@qyt-gujun ~]# cd /opt
[root@qyt-gujun opt]# mkdir euler
[root@qyt-gujun opt]# chmod 1777 euler
[root@qyt-gujun opt]# su - gujun

[gujun@qyt-gujun ~]$ cd /opt/euler/
[gujun@qyt-gujun euler]$ touch 1.txt

[openeuler@qyt-gujun ~]$ cd /opt/euler/
[openeuler@qyt-gujun euler]$ rm -rf 1.txt
rm: 无法删除 '1.txt': Operation not permitted

    3.实验演示

    3.1.场景描述

    假设你是一家公司的Linux系统管理员。公司有一个名为 project_alpha的重要项目，需要三个部门协作：

    • 研发部：部门用户组为 dev_team。
    • 设计部：部门用户组为 design_team。
    • 产品部：部门用户组为 pm_team。

    现有以下用户：

    • 研发部员工：alice(主组 dev_team), bob(主组 dev_team)
    • 设计部员工：charlie(主组 design_team)
    • 产品部员工：david(主组 pm_team)

    3.2.需求

    现在，请在 /opt目录下为项目 project_alpha建立一个共享文件夹 /opt/project_alpha。你需要配置这个目录的权限，以满足以下所有需求：

    1. 所有权：该目录由 root 用户和 dev_team组共同所有。
    2. 研发部权限：dev_team组的成员（alice, bob）必须能在该目录中创建、删除、重命名任何文件或子目录。
    3. 设计部与产品部权限：design_team和 pm_team组的成员（charlie, david）可以读取和进入该目录，但不能创建或删除文件。
    4. 文件继承：在该共享目录中新创建的任何文件，应自动允许 dev_team组有读写权限，而 design_team和 pm_team组只有读权限。
    5. 隔离性：系统上的其他用户（不属于以上任何组）不能访问该目录。

    3.3.创建用户和组

    [root@qyt-gujun ~]# groupadd dev_team
[root@qyt-gujun ~]# groupadd design_team
[root@qyt-gujun ~]# groupadd pm_team

[root@qyt-gujun ~]# useradd -g dev_team alice
[root@qyt-gujun ~]# useradd -g dev_team bob
[root@qyt-gujun ~]# useradd -g design_team charlie
[root@qyt-gujun ~]# useradd -g pm_team david

    3.4.创建目录并设置权限

    [root@qyt-gujun ~]# mkdir /opt/project_alpha
[root@qyt-gujun ~]# chown root:dev_team /opt/project_alpha/
