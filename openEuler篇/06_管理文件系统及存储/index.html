    06_管理文件系统及存储

    1.文件系统基础概念

    1.1.磁盘类型

    根据硬盘材质：

    • IDE（集成电路接口，并口）：已淘汰，笨重且磁盘容量小。
    • SCSI（小型计算机系统接口，并口）：用于服务器，噪音大、稳定性强、支持热插拔、价格略贵。
    • SATA（串行ATA，串口）：主流家用/桌面级接口，性价比高、普及度广。
    • SAS（串行连接SCSI，串口）：用于服务器，结合了SCSI的高可靠性和SATA的串行技术优点，性能更强且兼容SATA硬盘。
    • FC（光纤通道）：需要专用光纤通道卡和交换机，用于构建高性能、高可靠的企业级存储网络（SAN），成本极高。
    • Virtio（虚拟I/O）：不是物理接口，是虚拟化环境中用于加速虚拟机I/O性能的半虚拟化驱动标准。

    根据硬盘材质：

    • HDD（机械硬盘）：容量大、价格低，适合存放不常用的文件，稳定耐造。
    • SSD（固态硬盘）：速度快、价格高、体积小，适合作为系统盘使用。

    1.2.磁盘标识

    在Linux中硬盘等硬件设备也以文件的形式存在，系统内核中的udev设备管理器会自动规范硬件的名称，目的是让用户通过设备的文件名可以了解设备的大致信息。

    udev设备管理器会以守护进程的形式运行并侦听内核发出的信号来管理/dev/目录下的设备文件。

    Linux系统是以硬盘等设备的接口判断其硬盘类型，然后给予相应的文件名，如下表：

    硬盘 文件名称
    IDE设备 /dev/hd[a-d]
    SCSI/SATA/U盘 /dev/sd[a-p]
    virtIO /dev/vda

    hd、sd、vds代表的是硬盘的类型，a-p代表硬盘的序号（顺序），但是硬盘的序号不是由服务器上的硬盘插槽决定的，而是系统内核的识别顺序来决定的。默认从a开始分配。

    在Linux中可使用lsblk命令查看系统的磁盘使用情况：

    [root@qyt-gujun ~]# lsblk
NAME   MAJ:MIN RM  SIZE RO TYPE MOUNTPOINTS
sda      8:0    0  100G  0 disk
├─sda1   8:1    0    1G  0 part /boot
├─sda2   8:2    0    2G  0 part [SWAP]
└─sda3   8:3    0   97G  0 part /
sr0     11:0    1  3.5G  0 rom
    • name：标识设备的名称。
    • MAJ:MIN：显示主次设备号。
    • 主设备号（Major Number）：标识设备类型（如硬盘、终端、声卡等），由内核分配给不同的设备驱动程序。
    • 次设备号（Minor Number）：标识同一设备类型下的具体实例（如第几块硬盘、第几个分区等）。
      • 主设备号 8：表示这是一个 SCSI/SATA 磁盘设备（内核中 SCSI 磁盘驱动的主设备号通常是 8）。
      • 次设备号 0：表示这是系统中的第一块 SCSI/SATA 磁盘（sda）。
    • RM：标识是否是移动设备，1代表是移动设备，0代表不是。
    • SIZE：代表硬盘的大小。
    • RO：代表该设备是否是只读设备。
    • TYPE：代表设备的类型。
    • MOUNTPOINTS：代表设备被挂载的路径。

    1.3.分区

    分区（Partition）是指将一块物理硬盘在逻辑上划分为多个独立的存储区域，每个分区可以视为一个独立的逻辑磁盘，拥有自己的文件系统、目录结构和存储空间。但是硬盘不是必须分区才能使用的。

    1.3.1.分区的好处
    1. 隔离数据
    2. 将系统文件、用户数据、应用程序分开存放，避免互相干扰（例如系统崩溃时用户数据不受影响）。
    3. 多系统共存
    4. 在同一块硬盘上安装多个操作系统（如 Windows + Linux），每个系统占用独立分区。
    5. 性能优化
    6. 将频繁读写的目录（如 /home、/var）单独分区，减少磁盘碎片。
    7. 安全控制
    8. 为不同分区设置不同的访问权限（如只读、加密）。
    9. 灵活管理
    10. 可以单独格式化、挂载、备份或调整某个分区，而无需影响其他分区。
    1.3.3.什么是分区表？

    分区表类似于一块硬盘的目录或地图，物理硬盘是一个原始的、巨大的存储空间。

    硬盘最开始的扇区存在一段特殊的数据，告诉操作系统：

    1. 这块硬盘被分成了几个部分（分区）？
    2. 每个分区从哪里开始，到哪里结束？
    3. 每个分区是什么类型的（比如，是 Windows 的 NTFS 分区，还是 Linux 的 EXT4 分区）？
    4. 哪个分区是可以启动操作系统的？

    如果没有分区表，操作系统就无法识别和管理硬盘上的分区，就像一本书没有目录，你无法直接找到具体的章节。

    1.3.4.MBR分区表

    MBR是传统的分区表方案，从1983年沿用至今，它位于硬盘的第一个扇区（512字节）。

    在MBR分区方案中，由主分区、扩展分区、逻辑分区三种分区组成，其缺点是最多只支持4个主分区，最大只支持2TB的硬盘，对于大于2TB的硬盘，MBR无法管理超出的空间。

    1.3.4.1.工作原理与结构

    MBR这个512字节的区域包含三部分：

    1. 引导代码（446字节）：存储一小段程序，用于启动操作系统。
    2. 分区表（64字节）：这就是核心，只能记录 4 个主分区的信息，记录一个分区就需要使用16字节，所以最大只支持4个主分区。
    3. 结束标志（55 AA，2字节）：用于标记MBR有效。

    1.3.4.2.扩展分区与逻辑分区

    只有四个主分区很明显是不够用的，很多时候我们都需要更多的分区。这个时候就需要配合扩展分区与逻辑分区。

    • SCSI接口硬盘最多有4个主分区，12个逻辑分区，总共15个分区。
    • IDE接口硬盘最多有4个主分区，逻辑分区60个，总共63个分区

    扩展分区本质上也属于主分区的一种，它的作用是产生逻辑分区。

    实现方式：

    1. 将第四个主分区设置为扩展分区，扩展分区不存储数据，作为逻辑分区的容器。
    2. 扩展分区只是指向一个链表结构，用于管理逻辑分区。这样一来只需要占用一个主分区的位置，就可以有多个逻辑分区。
    3. 扩展分区的起始位置存储了一个EBR(Extended Boot Record)，类似于MBR，它只记录：
    4. 当前逻辑分区的信息。
    5. 下一个 EBR 的位置（形成链表）。
    6. 每个逻辑分区的起始位置都对应一个EBR，通过链表连接。
    7. 最后一个EBR的下一指针为NULL，表示链表结束。
    MBR
├─主分区1
├─主分区2
├─主分区3
└─扩展分区（指向 EBR1）
    ├─EBR1（逻辑分区1 + 指向 EBR2）
    ├─EBR2（逻辑分区2 + 指向 EBR3）
    └─EBR3（逻辑分区3 + NULL）
    1.3.5.GPT分区表

    GPT（GUID Partition Table）是一种现代的分区表标准，用于替代传统的 MBR（Master Boot Record）。它解决了MBR的诸多限制，并提供了更高的灵活性、安全性和对大容量硬盘的支持。

    特性 说明
    支持大容量硬盘 理论最大支持 18 EB（Exabytes，1 EB = 100万 TB），远超 MBR 的 2TB 限制。
    分区数量无严格限制 通常支持 128 个主分区（Windows 默认），Linux 可支持更多。
    更高的安全性 使用 CRC32 校验 和 备份分区表，防止数据损坏。
    唯一标识符（GUID） 每个分区都有一个 全局唯一标识符（GUID），避免冲突。
    兼容 UEFI 启动 现代计算机使用 UEFI + GPT 组合，替代传统的 BIOS + MBR。

    GPT的分区信息存储在硬盘的两个位置：

    1. 主 GPT 头（Primary GPT Header）：位于硬盘的 LBA 1（第 2 个扇区，LBA 0 是保护性 MBR）。
    2. 备份 GPT 头（Backup GPT Header）：位于硬盘的 最后一个扇区。
    1.3.6.Linux主流分区工具：
    1. fdisk：旧版本仅适用于MBR(MS-DOS)分区表，新版本也可适用于GPT分区表。交互式命令行工具，手动保存后才会对硬盘进行修改。
    2. gdisk：适用于GPT分区表，交互式命令行工具，手动保存后才会对硬盘进行修改。
    3. parted：同时支持GPT和MBR分区表，支持非交互式命令行操作（适合脚本自动化）。

    1.4.文件系统

    文件系统（File System）是操作系统用于明确存储设备或分区上的文件存储和检索方式的一套机制。作用如下：

    1. 数据组织方式：如何将数据分割为文件和目录
    2. 存储方法：如何在物理介质上安排和存储这些文件
    3. 元数据管理：如何记录文件属性（名称、大小、权限等）
    4. 访问控制：如何控制对文件的读写权限

    文件系统的核心组件：

    组件 功能描述
    超级块(Superblock) 存储文件系统的元信息（如大小、状态、块大小等）
    索引节点(Inode) 存储文件元数据（权限、所有者、大小、位置等）
    目录结构 组织文件和子目录的层次结构
    数据块 实际存储文件内容的区域
    分配表 记录哪些块已被使用/空闲（如FAT、位图等）
    1.4.1.文件系统工作原理

    当我们在Linux中创建一个新文件时：

    1. 分配inode：文件系统为新文件分配一个inode，存储元数据
    2. 更新目录项：在父目录中添加新条目，关联文件名和inode
    3. 分配数据块：根据文件大小分配一个或多个数据块
    4. 更新分配表：标记这些数据块为已使用
    5. 写入数据：将文件内容写入分配的数据块
    1.4.2.inode工作原理

    用户创建文件过程：

    1. 在父目录中分配一个新的目录项
    2. 文件系统分配一个空闲inode
    3. 将文件名与inode编号关联写入目录项
    4. 初始化inode元数据（权限、所有者等）
    5. 为文件数据分配存储块并更新inode指针

    用户请求访问 "/home/user/file.txt" 1. 在目录"/home/user"中找到"file.txt"对应的inode编号 2. 通过inode编号读取inode内容 3. 从inode获取权限信息进行访问控制 4. 通过inode中的块指针定位文件数据 5. 读取/修改数据块内容

    1.4.3.EXT4与XFS

    在Linux的文件系统中XFS和EXT4是最常见的两个选项。

    EXT4：

    • 优势：
    • 兼容性强：支持几乎所有的Linux发行版，即使是较老的系统也能稳定运行。
    • 碎片化管理好：对于小文件和频繁读写场景，EXT4具有较好的碎片整理能力，性能稳定。
    • 支持文件系统检查（fsck）：在系统崩溃后，EXT4允许运行fsck工具进行数据恢复。
    • 支持动态缩小分区：可在不格式化的情况下缩小分区，这对存储管理非常灵活。
    • 缺点：
    • 大文件性能不如XFS：如果存储的是大文件（如视频、数据库），EXT4在写入速度上略慢。
    • 在线扩展支持有限：扩展EXT4分区需要先卸载文件系统，影响可用性。

    在日常办公、开发环境或者小型网站服务器，选择EXT4是最稳妥的方案。

    XFS：

    • 优势：
    • 大文件处理能力强：XFS设计之初就考虑了高性能，并行写入能力远胜于EXT4`。
    • 在线扩展更简单：可以在系统运行时直接扩展XFS分区，无需卸载。
    • 适合高并发写入：如果你的服务器需要同时处理大量读写请求，XFS通过日志结构优化了I/O性能。
    • 支持超大存储：单个XFS分区可达8EB，适用于企业级存储。
    • 缺点：
    • 不支持文件系统检查（fsck）：XFS文件系统损坏后，无法使用fsck进行修复，只能通过备份恢复。
    • 不适合作为根文件系统：许多Linux发行版不建议将XFS作为根系统分区，可能会遇到兼容性问题。
    • 不能缩小分区：XFS只支持扩展，不支持缩小，因此在分区时需要慎重考虑大小。
    使用场景 推荐文件系统
    个人 PC / 开发环境 EXT4
    数据库服务器（Mysql） XFS
    大数据存储（如视频、日志、备份） XFS
    小型网站、应用服务器 EXT4
    RAID + 高并发写入（如企业存储） XFS
    1.4.4.格式化（创建文件系统）
    mkfs [选项] [-t 文件系统类型] [文件系统选项] 设备 [大小]

    创建ext4文件系统：

    # 基本用法
sudo mkfs -t ext4 /dev/sdb1

# 等价专用命令
sudo mkfs.ext4 /dev/sdb1

# 带卷标和块大小
sudo mkfs.ext4 -L "mydata" -b 4096 /dev/sdb1

    创建XFS文件系统：

    # 基本用法
sudo mkfs -t xfs /dev/sdb1

# 带日志大小设置
sudo mkfs.xfs -l size=128m /dev/sdb1

# 带条带化参数（适合RAID）
sudo mkfs.xfs -d su=64k,sw=4 /dev/sdb1

    1.5.挂载

    挂载是将存储设备上的文件系统与Linux目录树中的某个目录（称为挂载点）关联的过程，使得该文件系统的内容可以通过这个目录访问。

    挂载的操作就像是将USB驱动器插入电脑：

    • 存储设备 = USB驱动器本身
    • 文件系统 = USB上的数据组织结构
    • 挂载点 = 电脑上显示的"可移动磁盘"图标
    • 挂载操作 = 插入USB后系统使其可用的过程
    1.5.1.mount命令
    mount [-选项] [设备] [挂载点]
mount [-选项] [-t 文件系统类型] [-o 挂载选项] 设备 挂载点
    1. 挂载设备到目录
    sudo mount /dev/sdb1 /mnt/data
    1. 指定文件系统类型
    sudo mount -t ext4 /dev/sdb1 /mnt/data
sudo mount -t xfs /dev/sdc1 /mnt/backup
sudo mount -t ntfs /dev/sdd1 /mnt/windows
    选项 描述 示例
    -t 指定文件系统类型 -t ext4, -t nfs
    -o 指定挂载选项 -o ro, -o noexec
    -a 挂载 /etc/fstab中的所有文件系统 mount -a
    -r 只读挂载（等同于 -o ro） mount -r /dev/sdb1 /mnt
    -v 显示详细输出 mount -v /dev/sdb1 /mnt
    -n 不写入 /etc/mtab文件 mount -n /dev/sdb1 /mnt
    -l 显示文件系统标签 mount -l
    --bind 绑定挂载（目录到目录） mount --bind /old /new
    1.5.2.fstab

    使用mount命令进行挂载是临时的方式，如果需要永久定义挂载操作，需要将配置写入到/etc/fstab文件中。

    /etc/fstab(文件系统表) 是Linux系统中用于定义自动挂载文件系统的配置文件，它决定了系统启动时哪些文件系统会被自动挂载以及如何挂载。

    基本格式

    每行定义一个挂载项，包含6个字段，字段间用空格或制表符分隔：

    <设备> <挂载点> <文件系统类型> <挂载选项> <dump备份标志> <fsck检查顺序>
    字段位置 名称 描述 示例
    1 设备 要挂载的设备或资源 /dev/sdb1, UUID=xxx, LABEL=mydata
    2 挂载点 挂载到的目录路径 /mnt/data, /home
    3 文件系统类型 文件系统类型 ext4, xfs, nfs, swap
    4 挂载选项 挂载时的选项 defaults, noatime, ro
    5 dump备份 是否被dump备份工具使用 0(不备份), 1(备份)
    6 fsck检查 文件系统检查顺序 0(不检查), 1(根), 2(其他)

    查看设备UUID：

    [root@qyt-gujun ~]# blkid /dev/sdb

    常用挂载选项：

    1. 访问权限控制：
    选项 描述 适用场景
    ro 只读挂载 保护重要数据不被修改
    rw 读写挂载（默认） 常规数据分区
    noexec 禁止执行程序 数据存储分区，增强安全
    nosuid 忽略SUID/SGID权限位 防止权限提升攻击
    nodev 不解释设备文件 安全敏感挂载点
    1. 时间戳处理：
    选项 描述 性能影响
    atime 更新访问时间（默认） 高I/O开销
    noatime 不更新访问时间 显著提升性能
    relatime 相对时间更新（推荐） 平衡方案
    strictatime 严格更新访问时间 最高准确性
    1. 性能优化选项：
    选项 描述 适用场景
    sync 同步写入（数据立即写入磁盘） 数据安全优先
    async 异步写入（默认） 性能优先
    data=writeback ext4的宽松日志模式 最高性能
    data=ordered ext4的默认日志模式 平衡方案
    data=journal ext4的完全日志模式 数据安全

    2.LVM

    2.1.理论概念

    LVM (Logical Volume Manager)是Linux环境下对磁盘分区进行管理的一种机制，它提供了比传统磁盘分区更灵活、更强大的存储管理能力。LVM的核心概念是将物理存储设备抽象化，形成一个更易于管理的逻辑视图。

    LVM的创建初衷是为了解决硬盘设备在创建分区后不易修改分区大小的缺陷。尽管对传统的硬盘分区进行强制扩容或缩容从理论上来讲是可行的，但是却可能造成数据的丢失。而LVM技术是在硬盘分区和文件系统之间添加了一个逻辑层，它提供了一个抽象的卷组，可以把多块硬盘进行卷组合并。这样一来，用户不必关心物理硬盘设备的低层架构和布局，就可以实现对硬盘分区的动态调整。

    2.1.1.LVM的主要组件
    1. 物理卷 (Physical Volume, PV)：实际的物理存储设备（如硬盘、分区或 RAID 设备）
    2. 卷组 (Volume Group, VG)：由一个或多个物理卷组成的存储池
    3. 逻辑卷 (Logical Volume, LV)：从卷组中划分出来的逻辑存储单元，可以像普通分区一样使用

    2.1.2.LE和PE

    PE（Physical Extent）物理区域：

    • PE 是卷组（VG）中空间分配的基本单位
    • 每个物理卷（PV）被划分为多个大小相等的PE
    • PE大小在创建卷组时确定，默认通常为 4MB

    PE的特点：

    1. 固定大小：一个卷组中的所有PE大小相同
    2. 不可分割：是LVM管理的最小存储单元
    3. 连续分配：在物理卷上连续分布

    设置方式：

    # 创建卷组时指定 PE 大小（默认为 4MB）
sudo vgcreate -s 8M my_vg /dev/sdb    # 设置 PE 大小为 8MB
sudo vgcreate -s 64M my_vg /dev/sdb   # 设置 PE 大小为 64MB

# 查看卷组的 PE 信息
sudo vgdisplay my_vg

    LE（Logical Extent）逻辑区域：

    • LE是逻辑卷（LV）中空间分配的基本单位
    • 每个逻辑卷被划分为多个大小相等的LE
    • LE大小与PE大小相同

    LE的特点：

    1. 与 PE 一一对应：每个LE映射到一个或多个PE
    2. 逻辑视图：在逻辑卷层面提供连续的存储视图
    3. 可跨物理卷：LE可以映射到不同物理卷上的PE
    逻辑卷 (LV)       卷组 (VG)       物理卷 (PV)
+----------+     +----------+    +----------+
|   LE 0   | --> |   PE 0   |    | 物理位置 |
+----------+     +----------+    +----------+
|   LE 1   | --> |   PE 1   |    | 物理位置 |
+----------+     +----------+    +----------+
|   LE 2   | --> |   PE 5   |    | 跨物理卷 |
+----------+     +----------+    +----------+
|   LE 3   | --> |   PE 2   |    | 物理位置 |
+----------+     +----------+    +----------+

    查看PE/LE信息：

    # 查看物理卷的 PE 信息
sudo pvdisplay /dev/sdb

# 查看卷组的 PE 信息
sudo vgdisplay my_vg

# 查看逻辑卷的 LE 信息
sudo lvdisplay /dev/my_vg/my_lv

    创建逻辑卷时的PE/LE计算：

    # 当 PE 大小为 4MB 时
sudo lvcreate -L 10G -n my_lv my_vg
# 10GB = 10240MB，需要 PE 数量：10240 / 4 = 2560 个 PE/LE

# 使用 PE 数量创建（更精确）
sudo lvcreate -l 2560 -n my_lv my_vg  # -l 指定 LE 数量
