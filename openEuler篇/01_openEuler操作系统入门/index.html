    一、openEuler操作系统入门

    1.操作系统发展及Linux操作系统介绍

    1.1.什么是操作系统？

    操作系统（Operating System,OS）是管理计算机硬件与软件资源的系统软件，是硬件基础上的第一层软件，是所有其他软件运行的基础。操作系统就像是一个大管家，负责协调和分配所有资源，以提供给用户和其他软件方便的接口和环境的程序集合。

    操作系统的核心功能：

    • 进程管理：决定哪个程序使用CPU，何时使用，用多久（管任务）。
    • 内存管理：分配和回收内存空间，保证各程序间互不干扰（管核心资源）。
    • 文件系统管理：如何在硬盘上组织、存储、检索数据（管数据）。
    • 设备管理：管理和驱动所有外部设备，如键盘、鼠标、显示器、打印机等（管外设）。
    • 网络管理：控制和管理网络通信和数据传输（管网络）。

    1.2.操作系统发展历史

    操作系统并不是与计算机硬件一起诞生的，它是在人们使用计算机的过程中，为了满足两大需求：提高资源利用率、增强计算机系统性能，伴随着计算机技术及其应用的日益发展，而逐步地形成和完善起来的。

    1946年2月，在美国地宾夕法尼亚大学诞生了世界上的第一台电子计算机，该计算机是由大量的电子管组成，非常庞大。它的设计初衷是帮助美国国防部计算导弹地飞行轨迹。

    最开始的计算机是没有操作系统的，计算机采用手工操作，程序员将记录对应程序和数据的纸带或卡片装入计算机，然后启动输入机把程序和数据输入计算机内存，接着通过控制台开关启动程序针对数据运行。计算完毕后打印出计算结果，并卸下纸带，才能够让下一个用户上机。

    此时的计算机存在很多问题，如每次只可以用单用户单任务的执行，中途无法停止等。为此，操作系统的概念被提出，计算机操作系统也由批处理系统、多道程序系统、分时系统、以及最后的实时系统不断地向前发展。

    1.2.1.Unix发展史

    Multics

    1965年美国贝尔实验室、美国麻省理工学院和通用电气公司联合发起Multics工程计划，目标是开发一种交互式、具有多道程序处理能力的分时操作系统，用来取代当时广泛使用的批处理操作系统。该操作系统地理念是大而全，但是以失败告终。

    Unix

    失败之后，当时贝尔实验室的一名研究员，汤普逊（Unix之父）为了能在PDP-7计算机上运行自己编写的游戏，用汇编语言写出了一个新的操作系统Unics。该系统当时在贝尔实验室内部流传很广，由于用汇编语言写的，高度依赖硬件，系统没有移植性，所以汤普逊尝试用其他语言重写Unics但最终效果都不好。

    此时，丹尼斯.里奇（C语言之父）用C语言重写了Unics，最后正式推出了Unix操作系统。

    1.2.2.Linux发展史

    随着计算机硬件的发展，个人也开始慢慢可以买得起计算机了，早期计算机只有巨头公司和大学才有能力购买。随着使用人数增加，来了了大量的经济利益。于是AT&T美国电话电报公司，贝尔实验室是他的一个下属机构，它回收了Unix版权，从此Unix不再是免费的系统，需要付费使用。

    谭邦宁教授（外国人）为了更好的教学操作系统方面的知识，在Unix不公开的情况下，自己写了一个操作系统Minix(mini-Unix)，这个系统完全兼容Unix系统上的所有软件，谭邦宁教授在教学的同时也售卖这个操作系统。

    林纳斯（Linux之父）也是Minix的购买者之一，开始对Minix学习并研究，最后自己写出了我们熟知的Linux系统。他公开了Linux的源代码，并邀请其他人与他一起完善Linux，所有人都可以免费使用它。

    1.3.开源

    开源的含义是开放源代码，任何人都可以区查看、修改以及使用。闭源软件就是普通的商业版权软件，代码是封闭的，只有作者可以查看和修改。

    Richard Stallman是有史以来最伟大的几名黑客之一，他曾经买过一个商业软件，结果遇到一点小问题，于是他去找软件公司寻求帮助，结果被拒绝。一气之下创立了自由软件基金会，发布了大名鼎鼎的GPL协议，至今为止该协议依然是最著名的开源协议。

    另外，开源不等于免费，源代码虽然可以免费提供，但是软件相关的服务，例如编译、维护、升级等是需要付费的。

    Linux可以有如此巨大的成就，这要归功于Linus的开源、免费的理念，让全世界范围内的专家和爱好者都可以参与到Linux项目中，使其日益壮大。

    1.4.Linux发行版

    Linux本身是一个内核，内核是操作系统的核心部分，负责管理计算机的硬件资源，为其他软件提供运行的基础。只有一个内核是无法使用的，用户需要一个完整的操作系统环境，至少还需要：

    • 系统工具：GNU项目提供的核心工具（如bash shell、cp、mv、ls等命令）。
    • 软件包管理工具：用于安装、更新、卸载软件的工具。
    • 桌面环境：图形用户界面。
    • 应用软件：浏览器、办公软件等。

    Linux发行版是由个人、团队或公司，将Linux内核与各种必须的软件和程序包组合起来，并附加上自己的特色（如软件包管理工具、配置工具、桌面环境等），所构成的一个完整的、可以安装使用的操作系统。

    自Linux诞生以来，先后出现的发行版已经有数百种之多。有的昙花一现消失在历史长河中，有的不断进化成为主流的Linux发行版。

    1.4.1.国产操作系统

    国产Linux操作系统是指由中国公司或机构主导开发、维护，以Linux内核为基础，并深度融合了本土化应用、安全加固和特定软硬件生态的操作系统发行版。信创计划。

    流派 基于的发行版 特点 主要代表
    Debian/Ubuntu 系 Debian 或 Ubuntu 优点：桌面生态丰富，软件包新，易用性好，社区活跃。 缺点：企业级支持和服务相对较弱（但正在加强）。 Deepin (深度) Ubuntu Kylin (优麒麟)
    Red Hat 系 Fedora/CentOS (尤其是 RHEL) 优点：极端稳定，安全性和可靠性高，长期支持，是企业级和服务器市场的首选。 缺点：桌面软件相对保守，新技术跟进慢。 OpenEuler (欧拉) Anolis OS (龙蜥) 统信UOS 麒麟软件 (银河麒麟/中标麒麟)
    1.4.2.openEuler

    openEuler最初由华为开发，并于2019年正式开源，捐赠给开放原子开源基金会进行运营，它的前身是EulerOS。社区官网：https://www.openeuler.openatom.cn/

    openEuler本身是开源社区版，类似于Fedora和RHEL的关系。商业公司会基于openEuler社区版制作自己的商业发行版，提供企业级的技术支持和服务。

    • 麒麟软件：推出了基于openEuler的 银河麒麟高级服务器操作系统 V10。
    • 统信软件：也发布了基于openEuler的服务器版系统。

    openEuler不是一个面向普通消费者的桌面系统，而是一个面向未来的企业级服务器操作系统。 它的战略意义在于：

    • 技术自立：通过开源社区的模式，掌握了操作系统发展的主动权。
    • 生态共赢：连接了芯片、硬件、软件厂商，构建了一个繁荣的国产基础软件生态。
    • 全球参与：作为一个开源项目，它也欢迎全球的开发者和公司参与贡献，使其成为具有国际影响力的开源项目。

    openEuler的版本分类

    社区版按照交付年份和月份进行版本号命名，例如openEuler 20.09于2020.9发布。

    社区版分为长期支持版本和创新版本：

    • 长期支持版本：发布间隔周期为2年，提供4年社区支持。社区首个LTS版本openeuler 20.03 LTS于2020.3发布。偶数年3月发布新一代LST首版本，偶数年12月，奇数年6月、12月发布对应SP版本。

    • 社区创新版本：openEuler每隔6个月会发布一个社区创新版本，提供6个月社区支持。偶数年9月，奇数年3、9月发布创新版本。

    • 目前LTS版本全版本生命周期4年（ 2+2 ），到生命周期结束前半年~1年由相关团队组建联合维护团队，申请延长至6年,单个版本生命周结束前，以邮件和公告的方式提前3个月知会
    • LTS版本SP版本生命周期原则上按照小SP（6月份Release，可选） 9个月，大SP （12月份Release）24个月执行；大规模使用建议选择大SP
    • SP0默认执行大SP策略，可基于社区使用情况和社区规则提前半年~1年审视是否提前结束；SP3作为LTS最后一个SP，随LTS全版本生命周期结束
    • Maintenance Support：CVE、Bugfix，新硬件支持和少量新特性（保证LTS内前向兼容的情况）,Extend Support：修复” 主要”以上CVE和Bug

    2.使用openEuler操作系统

    2.1.系统结构

    • 操作系统内核：Linux内核是操作系统核心，负责直接管理硬件资源（cpu、内存、磁盘网络等），并为上层软件提供基础服务。
    • Shell：常见Shell包括Bash、Zsh、Fish等，openEuler默认登录shell是bash。
    • 命令行解释器：shell是一个用C语言编写的程序，是用户与操作系统内核交互的“翻译官”。它解析用户输入的命令，调用内核功能执行任务（如创建文件、运行程序等），并将结果返回给用户。
    • 脚本引擎：支持运行自动化脚本。
    • 终端：输入输出界面，终端是一个程序，提供命令行交互的窗口环境。
    • 早期终端是物理设备，现在终端是软件模拟的（终端模拟器）。

    举个不恰当的例子：

    1. 一位美国的作者出版了一本书（Kernel）
    2. 国内的某位大牛将这本书进行翻译并出版（Shell）
    3. 我（User）到书店把这本纸质书（Terminal）买回来浏览

    2.3.关机与重启

    注意：大多数与电源相关的命令都是需要root权限的，如果你是普通用户需要执行电源相关命令需要加上sudo。

    2.3.1.shutdown命令

    shutdown命令允许在预定的时间将系统关机，并向当前系统上的所有用户发送通知。

    shutdown [选项] [时间] [警告信息]
    选项 作用
    -h或 --halt 关机（默认行为）
    -P或 --poweroff 关机并断电（同 -h）
    -r或 --reboot 重启系统
    -c或 --cancel 取消已计划的关机
    -k 仅发送警告，不真正关机
    --no-wall 不发送广播消息
    1. 拒绝新登录：
    2. 创建 /run/nologin或 /etc/nologin，阻止新用户登录。
    3. 发送警告：
    4. 通过 wall广播消息给所有终端。
    5. 关闭服务：
    6. 按顺序停止 systemd/SysVinit 服务。
    7. 卸载文件系统：
    8. 确保所有数据写入磁盘（sync）。
    9. 执行关机：
    10. 调用 poweroff或 halt完成关机。

    立即关机

    shutdown -h now

    定时关机

    shutdown -h +10

    指定时间关机

    shutdown -h 23:00

    取消关机计划

    shutdown -c

    立即重启

    shutdown -r now

    定时重启

    shutdown -r +10
    2.3.2.poweroff

    poweroff是Linux系统中用于立即关闭系统并切断电源的命令，它比 shutdown更直接，适用于快速关机场景。

    sudo poweroff [选项]
    选项 作用
    -f或 --force 强制关机（不推荐，可能损坏数据）
    2.3.3.systemctl

    systemctl是Systemd系统的核心管理工具，用于控制 Linux 系统的启动、停止、关机和重启。相比传统的 shutdown和 reboot，它更现代化。

    命令 作用 等效传统命令
    sudo systemctl poweroff 关机并断电 sudo shutdown -h now
    sudo systemctl reboot 重启系统 sudo reboot
    sudo systemctl halt 停止系统但不断电 sudo halt
    sudo systemctl suspend 挂起到内存（睡眠） -
    sudo systemctl hibernate 挂起到磁盘（休眠） -
    sudo systemctl hybrid-sleep 混合睡眠（内存+磁盘） -
    2.3.4.reboot
    sudo reboot
    • 最常用的重启命令
    • 会正常关闭所有服务后再重启
    • 适用于大多数 Linux 发行版
    2.3.5.init

    init是Linux系统中 第一个被执行的进程（PID=1），它是所有其他进程的父进程，负责系统的启动、运行级别切换和关机流程。

    sudo init [运行级别]
    运行级别 模式 说明
    0 Halt 关机
    1 Single User Mode 单用户模式（救援模式）
    2 Multi-User 多用户模式（无网络）
    3 Full Multi-User 完整多用户模式（命令行）
    4 Unused 保留未使用
    5 Graphical 图形界面模式
    6 Reboot 重启

    2.4.普通用户提权

    root是Linux系统中的管理员用户，类似于Windows系统中的Administrator。root用户拥有当前系统中最高权限，甚至可以无限的破坏系统。在生产环境中一般不会直接使用root用户。

    通过命令行的命令提示符可得知当前用户的身份，$代表普通用户，#代表root用户。

    但我们在实际使用的过程中仅仅只拥有普通用户的权限是举步维艰的，很多操作都需要有root权限才可以操作。此时，我们可以通过两种方式来解决：

    1. 通过su命令切换到root用户执行操作。
    2. 通过sudo使普通用户临时拥有root用户的权限。

    仔细想一下，这两种方法实际上只是在你需要用到root权限时加了一个额外操作，意在提醒你当前执行的是高危操作要小心，另外会记录到日志里。

    2.4.1.加入wheel组

    并不是创建出来的普通用户都可以执行sudo或切换到root用户的，需要将普通用户加入到wheel组中。

    wheel组是 Unix/Linux 系统中 用于集中管理管理员权限的特殊用户组，成员可被授予 sudo权限，而无需直接使用 root账户。

    1. 创建普通用户（此时无法切换到root用户，也无法使用sudo）
    [root@qyt-gujun ~]# useradd zhangsan
[root@qyt-gujun ~]# passwd zhangsan
Changing password for user zhangsan.
New password:
Retype new password:
passwd: all authentication tokens updated successfully.
    1. 将用户添加到wheel组
    [root@qyt-gujun ~]# usermod -aG wheel zhangsan
# -a表示追加操作，保证用户不会被移出原有组
# -G指定用户要加入的附加组
[root@qyt-gujun ~]# groups zhangsan
zhangsan : zhangsan wheel
    2.4.2.sudo
    sudo [选项] 命令
    • -u 用户名：以指定用户身份运行命令（默认是 root）。
    • -l：列出当前用户可执行的命令。
    • -v：刷新 sudo 凭证缓存（延长有效期）。
    • -k：清除 sudo 缓存（要求下次使用时重新输入密码）。
    • -s：启动一个 root shell（相当于 sudo su）。
    • -i：以root身份启动登录Shell。

    sudo的权限控制由etc/sudoers文件定义，使用visudo命令进行编辑，语法如下：

    用户名/组名   主机名=(可切换的用户) 可执行的命令

    %wheel  ALL=(ALL)       ALL

    该字段为默认值，代表允许wheel组用户执行所有命令。

    2.4.3.su

    su(Switch User)是Linux/Unix系统中用于切换用户身份的命令，默认切换到root用户。与sudo不同，su直接启动目标用户的shell环境，适用于需要长时间以其他用户身份操作的场景。

    • -或 -l：模拟登录（加载目标用户的环境变量，如 ~/.bashrc）。
    • -c "命令"：以目标用户身份执行单条命令后退出。
    • -s：指定要启动的 shell（如 -s /bin/bash）

    切换到root用户：

    su          # 切换到 root，不加载环境变量（需输入 root 密码）
su -        # 切换到 root 并加载环境变量（推荐）

    切换到其他用户：

    su - alice      # 切换到用户 "alice" 并加载其环境
su alice        # 切换到 "alice"，但保留当前环境变量

    以目标用户身份执行单条命令：

    [root@qyt-gujun ~]# su -c "whoami" zhangsan
zhangsan

    与sudo的区别：

    特性 su sudo
    密码要求 需输入目标用户的密码 需输入当前用户的密码
    权限范围 完全切换到目标用户权限 按需授予单条命令权限
    环境变量 可加载目标用户的环境（su -） 默认继承当前用户环境
    适用场景 需长时间以其他用户身份操作 临时执行特权命令
    安全性 需共享 root 密码，风险较高 细粒度控制，更安全

    2.6.swap空间

    swap（交换空间）是Linux系统中用于扩展内存的虚拟内存技术。当物理内存不足时，系统会将部分不活跃的内存数据临时存储到磁盘中，从而避免进程因内存不足被强制终止。

    swap分区还可使我们的系统支持休眠，当系统休眠时，将整个内存内容保存到swap，以便恢复时重新加载。

    另外，即使物理内存充足，Linux内核也会适度使用swap，优化内存管理（如长时间未使用的进程）。

    使用SWAP虽然可以避免系统因内存不足而崩溃，但从SWAP读取数据的速度比从RAM读取慢得多。因此，频繁的SWAP操作可能会导致系统性能下降，称为“交换抖动”（swap thrashing）。

    2.7.CLI与GUI

    GUI(Graphical User Interface)图形用户界面。使用鼠标作为输入工具，使用按钮、菜单、对话框等进行交互，追求易用。

    CLI(Command Line Interface)命令行界面，用户界面字符化，使用键盘作为输入工具，输入命令、选项、参数执行程序，追求高效。

    • 命令行更高效：

    • Linux系统中使用键盘操作速度要比鼠标更快。

    • 图形化界面不可重复，而命令行可以编写脚本完成所有过程。

    • 图形化界面开销大：运行图形化界面会占用很多的系统资源，运行命令行可以让系统资源释放给它更应该做的事情。

    • 命令行有时是唯一选择：

    • 大部分软件可能没有图形化管理工具，配置和管理依旧需要使用命令行。
